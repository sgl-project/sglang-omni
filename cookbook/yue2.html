YuE2#

YuE2 generates 48 kHz stereo music from lyrics and a style description. Its shared transformer predicts an ABC score and semantic tokens autoregressively, then generates acoustic latents with flow matching. A separate FP32 VAE decodes the audio.

The YuE2 and YuE2-Vae weights are CC BY-NC 4.0; commercial use is not permitted.

Start the server#

Install SGLang-Omni following Installation, then start one CUDA worker:

CUDA_VISIBLE_DEVICES=0 sgl-omni serve \
  --model-path m-a-p/YuE2-3B \
  --port 8000

The pipeline has two stages, both on GPU 0 by default; --yue2_acoustic.gpu 1 moves the acoustic stage to a second GPU. The AR stage runs the BF16 transformer on the SGLang engine with continuous batching, paged KV cache and CUDA graphs; it generates the ABC score and then the semantic tokens. The acoustic stage loads the BF16 transformer and FP32 decoder to run flow matching and VAE decoding. On one GPU it reads the transformer’s AR weights from the AR stage’s memory instead of loading a second copy, which saves about 3.3 GiB; --yue2_acoustic.factory.share_ar_weights false makes it load its own. --yue2_ar.factory.max_concurrency sets how many rows decode together (default 16); a request with classifier-free guidance uses two rows. The KV cache holds 65,536 tokens by default, enough for several full songs at once; requests beyond it wait for a free slot, and a request too large to ever fit is rejected. Raise it with --yue2_ar.engine.max_total_tokens, or size it in bytes with --yue2_ar.engine.kv_cache_bytes.

Both the transformer and decoder accept local checkpoint directories or Hugging Face model identifiers. The default decoder is m-a-p/YuE2-Vae. Select the benchmark decoder with --yue2_acoustic.factory.vae_path m-a-p/YuE2-Vae-legacy. Checkpoint identifiers can pin a revision with repository@revision.

Generate a song#

curl http://localhost:8000/v1/audio/speech \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "m-a-p/YuE2-3B",
    "input": "[Verse]\nMorning light is shining through\nEvery road leads back to you",
    "instructions": "Gentle acoustic pop, warm female vocals, piano and guitar",
    "seed": 42,
    "max_new_tokens": 9000,
    "response_format": "wav"
  }' \
  --output song.wav

input is plain lyrics and instructions is the required musical style; an empty string leaves the style tag empty. seed controls each generation phase independently. max_new_tokens limits semantic audio tokens, excluding the ABC planning phase; it is a token budget, not a requested audio duration. The semantic sampling fields temperature, top_p, top_k and repetition_penalty are supported.

The response’s X-Finish-Reason is length if either planning or semantic generation reaches its token budget; it is stop when both phases finish normally. Increasing the semantic budget cannot repair a truncated ABC plan: adjust abc_max_tokens for that phase. Requests that exceed the model context fail instead of silently shortening their budgets.

Control the score and acoustic solver#

Model-specific settings use the existing stage_params field:

{
  "input": "[Verse]\nMorning light is shining through",
  "instructions": "Acoustic folk, gentle vocals",
  "seed": 42,
  "stage_params": {
    "synthesis": {
      "cot": "melody",
      "abc": "X:1\nT:Morning\nM:4/4\nL:1/4\nK:C\nC D E F | G A B c |",
      "ode_steps": 32
    }
  }
}

Setting

Meaning

cot

full plans melody and chords; melody plans melody; off skips score planning. Default: full.

abc

An optional supplied score, used without generating a new one. Requires full or melody.

abc_max_tokens

Planning budget. Default: 4096.

cfg_scale

Semantic classifier-free guidance. Defaults to 1.0 for score modes and 1.01 for off, matching the model’s generation protocol.

ode_steps

Midpoint flow-matching steps, at most 200. Default: 32.

Voice selection, reference-audio conditioning, speed changes and streaming output are unsupported. Cancellation is checked between AR tokens, acoustic solver evaluations and VAE tiles; an already submitted GPU operation finishes before cancellation takes effect.

Optional acceleration#

AR decoding always uses SGLang’s CUDA graphs, continuous batching and one-step lookahead: the next decode step launches before the host reads the current step’s tokens. Requests with classifier-free guidance decode as a pair of rows (conditioned and unconditioned) that stay together in each batch. Each request keeps its own seed, sampling parameters, token budgets and cancellation state.

On NVIDIA CUDA devices, enable the acoustic stage’s fused kernels with:

sgl-omni serve --model-path m-a-p/YuE2-3B \
  --yue2_acoustic.factory.fused_kernels true

fused_kernels uses sgl_kernel for RMS normalization, residual addition with normalization, Q/K normalization with RoPE, and SiLU activation with gating, and also fuses the QKV and gate/up projections (fuse_projections enables only the projection fusion). Fused kernels change BF16 rounding and acoustic latents.

Limitations#

The official YuE2 implementation offers additional optional execution modes that are not currently supported by this Omni integration:

  • Experimental AR FP8 quantization.

  • Low-VRAM weight offloading.

  • AR decoding with torch.compile.

Validation#

Run the CPU regression suite with:

pytest tests/unit_test/yue2 -q

Run the real-checkpoint smoke tests on one CUDA GPU with:

YUE2_MODEL_PATH=m-a-p/YuE2-3B pytest tests/test_model/test_yue2.py -q

These short tests start a server and cover the score modes, external ABC, CFG, concurrent requests, invalid requests, client disconnection and seeded reproducibility. They do not measure song quality. The tests are skipped unless YUE2_MODEL_PATH is set; it and YUE2_VAE_PATH accept local directories or revision-pinned identifiers.

Quality comparisons must use the same transformer revision, VAE revision, prompts, seeds and generation settings. The official WildSongBench protocol uses YuE2-Vae-legacy; scores from the standard decoder are not directly comparable to that baseline. Keep truncated outputs in evaluation and report them separately.
