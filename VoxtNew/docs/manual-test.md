# 真机验证清单（VoxtNew 0.1）

在 Mac 上按顺序点一遍：第一次打开和下载模型、转录、翻译、转写、应用增强、词典，再看模型进程（删除、崩溃、空闲卸载、退出、内存）、出错和离线时的表现，最后是首页、历史和设置。自动测试碰不到这些：权限、事件 tap、真实 App 的辅助功能、浏览器、浮窗的外观、真实麦克风下的本地模型。

真机上不用人守着就能测的部分，由第 10 节的自动测试覆盖：`mac-e2e.sh`（真实的辅助进程、用文件代替麦克风的录音链路、只读的辅助功能读取、Core Text 下的文字测量）和 `mac-regress.sh`（真实的两个语音识别模型、Silero、三个语言模型、评测的快速版、打包好的 app 以 `--smoke` 启动再退出）。**时间不够时，先跑第 10.6 节的回归，再做第 10.4 节的“人工补测清单”（约 15 分钟）**，其余各节作为完整回归。

- **必做部分约 80 分钟**，不含下载模型的时间（推荐的两个模型共 5.8 GB）。标 **〔可选〕** 的步骤时间够再做，不影响结论。
- 每一步写了三件事：**做** / **应看到** / **不对时看**。
- 文中的耗时来自 mac-air（M4，24 GB）的实测（[eval.md](eval.md)、[llm-models.md](llm-models.md)），只用来判断“差不多”；内存小或者同时跑着别的模型的 Mac 会慢一些。
- 发现问题时，记下步骤编号和时间，导出诊断（设置 → 诊断与关于 → 复制诊断信息，或“保存诊断包”），并截图。日志默认不含说的话（设置 → 隐私 → 记录说话内容）。

**排查时看这些地方**

| 名称 | 位置 |
|---|---|
| 日志面板 | VoxtNew 里按 ⇧⌘L（来源 `session`、`omni`、`llm`、`helper`） |
| 日志文件 | `~/Library/Logs/VoxtNew/voxtnew.log`（app，含 Omni 服务的启动、退出、卸载）、`helper.log`（辅助进程：热键、AX、粘贴、URL）、`llm.log`（voxtnew-llm 的 stderr） |

| 模型进程 | `pgrep -fl 'qwen3_asr_server\|voxtnew-llm\|voxtnew-helper'`：`qwen3_asr_server` 每个模型一个（命令行里的 `--model-directory …/models--<owner>--<name>/snapshots/<commit>` 说明是哪个：语音识别模型或 `vad.silero`），`voxtnew-llm` 最多一个 |
| 历史详情 | 每次会话的识别原文、结果、交付方式、用的语音识别模型和语言模型、各阶段耗时、命中的规则 |
| 系统设置 | 隐私与安全 → 辅助功能 / 麦克风；网络 → 代理 |

## 0. 准备（约 5 分钟）

**0.1 构建产物**
- app 里要有三样东西：辅助进程、Omni 运行时（语音识别）、voxtnew-llm（语言模型）。在 Linux 上执行其中一种：
  - 发布式构建（ad hoc 签名，没有更新源，结束时检查签名、运行时能从 app 里启动）：`MAC_DIR=code/VoxtNew scripts/mac.sh 'export PATH=/opt/homebrew/bin:$PATH; scripts/release.sh --runtimes $HOME/voxtnew-runtime'`（见 [release.md](release.md) §2.2，约 3 分钟）。
  - 开发构建：`MAC_DIR=code/VoxtNew scripts/mac.sh 'scripts/build-helper.sh && scripts/build-omni.sh && scripts/build-llm.sh && go tool mygo build'`。mac-air 上不用重编运行时：`cp -Rc ~/voxtnew-runtime/omni resources/darwin-arm64/omni && cp -Rc ~/voxtnew-runtime/llm resources/darwin-arm64/llm`，再 `scripts/build-helper.sh && go tool mygo build`。
- 结果在 `~/code/VoxtNew/build/darwin-arm64/VoxtNew.app`（约 280 MB）。
- 包是 ad hoc 签名：每次重打以后，macOS 都会忘掉授权（README 的“Signing during development”）。

**0.2 数据和模型**
- 第 1 节要从“第一次打开”开始：先退出 VoxtNew，把旧数据挪开（`mv ~/Library/Application\ Support/VoxtNew ~/voxtnew-data-old`），测完可以挪回来。
- mac-air 的磁盘紧（约 25 GB 空闲）。第 1 节真实下载的只有推荐的两个模型（5.8 GB）；其他三个用常驻的副本装进来（APFS 克隆，不占空间，第 1.5 步）。**不要删除或改动 `~/voxtnew-models` 和 `~/voxtnew-runtime`**，它们是各线程共用的。测完在 app 里删掉下载的模型，或者删掉整个数据目录。
- mac-air 的扬声器保持静音：测试都用真人对着麦克风说话，不要用扬声器放样本。

**0.3 打开 app 并授权**
- **做**：
  1. 打开 `VoxtNew.app`。第一次打开会弹出**设置引导**：第 1 节走一遍，先不要关。
  2. 在引导的“权限”一步（或者 设置（⌘,）→ 权限）授予麦克风和辅助功能。
  3. 如果系统设置里已经有一条旧的 VoxtNew 记录，而且它是打开的但不起作用，用 − 删掉，再重新添加。
- **应看到**：
  - 麦克风的授权弹窗以 VoxtNew 的名义出现；辅助功能打开后不用重启 app。
  - 权限一步（和权限页）的两项都显示已授权。
  - 侧边栏底部“设置”上方没有“辅助进程”的卡片（有就说明它没起来）；`pgrep -fl voxtnew-helper` 有一个进程。
- **不对时看**：`helper.log`，以及 设置 → 诊断与关于。

**0.4 其他准备**
- 先把这些 App 打开备用：TextEdit、备忘录、Chrome、Safari、Arc、Slack（或微信）、VS Code（或 Cursor）。
- 打开一个终端窗口，第 1、7、8 节要在里面看进程和代理。

## 1. 第一次打开：设置引导和本地模型（约 15 分钟，另加下载时间）

**1.1 引导的“模型”一步**
- **做**：在引导里点“开始设置”，过了权限一步，到“本地模型”。
- **应看到**：
  - 两行：“语音识别”是“精准语音识别”，“语言模型”是“均衡语言模型”，各有大小的标签（2.5 GB、3.3 GB）和一句“擅长什么”；没有模型系列、参数量或量化的名字。
  - 一个按钮“全部下载（5.8 GB）”。
- **不对时看**：截图。

**1.1b 〔可选〕其他 ActNow app 装过的模型**
- **准备**：这台 Mac 上装着 AudioSmith（或另一个 ActNow app），它下载过 Qwen3-ASR-1.7B-8bit（或 0.6B-4bit），模型在家族的模型库（默认 `~/.cache/huggingface/hub`）。
- **做**：第一次打开 VoxtNew（或 设置 → 通用 →“打开设置引导”），到“本地模型”一步。
- **应看到**：
  - 1.7B 在时：顶部卡片“已在这台 Mac 上找到 N 个模型 / 由 AudioSmith 安装 · 2.5 GB · 无需下载”，下面是“精准语音识别 · 声音检测”，主按钮“直接使用”和“选择模型…”；页脚的“继续”是次要按钮。语言模型那一行写“还需下载 3.3 GB”。点“直接使用”：卡片消失，语音识别那一行变成“可用：精准语音识别”，没有开始任何下载；`~/Library/Application Support/ActNow/models/claims/<VoxtNew 的 bundle id>.json` 里有这两个模型，`origin` 是 `reused`。
  - 只有 0.6B 时：语音识别那一行多一段“未安装精准语音识别，但已有快速语音识别（来自 AudioSmith）。先用它吗？”，“下载精准语音识别”和“先用快速语音识别”；点后者，这一行变成“可用：快速语音识别”。
- **不对时看**：截图；上面的 claims 文件；日志面板里 `family:` 的行。

**1.2 下载、进度、系统代理**
- **做**：
  1. 先在终端看系统代理：`scutil --proxy`（mac-air 上 HTTPS 代理是 `127.0.0.1:7897`）。
  2. 点“全部下载”。
  3. 下载开始后，点“继续”往下走（不用等）；转录那一步先不试。
- **应看到**：
  - 两行各有一条进度条；按钮消失，下面一行说明“模型在后台下载：可以继续下一步，进度条走满即可使用。”
  - 日志面板（来源 app）有一行 `models: system proxy https 127.0.0.1:7897`：没有 `https_proxy` 环境变量时，下载用系统代理。
  - mac-air 上走 7897 代理时约 16 MB/s（M3 用同一条路下载 8.6 GB 用了 9 分钟），推荐的两个模型大约 6 分钟。
  - 装好一个时出现提示“<名字> 已安装。”，引导里那一行变成“可用：<名字>”。
- **不对时看**：本地模型页的错误提示和它的 ⓘ（完整错误）；`ls ~/Library/Application\ Support/VoxtNew/models/.partial/`。

**1.3 取消和继续下载**（在 1.2 的下载过程中做，或者下载另一个模型时做）
- **做**：
  1. 打开本地模型页（侧边栏“本地模型”），在正在下载的“精准语音识别”卡片上点“取消”。
  2. 退出 VoxtNew（⌘Q），重新打开，进本地模型页。
  3. 点“继续下载”。
- **应看到**：
  - 取消后卡片显示“已暂停：已下载 x / 2.5 GB”，有“继续下载”和“删除”（删除已下载的部分）。
  - 重启后仍是“已暂停”，数字不变：已下载的部分保留在 `models/.partial/` 里。
  - 继续下载从原来的位置接着走，不从 0 开始；完成后卡片变成“已安装”和“占用 2.5 GB”。
- **不对时看**：日志面板；`du -sh ~/Library/Application\ Support/VoxtNew/models/.partial`。

**1.4 〔可选〕连不上 Hugging Face 时用镜像**
- **做**：在 系统设置 → 网络 → Wi-Fi → 详细信息 → 代理 里把“安全网页代理（HTTPS）”关掉（中国大陆的网络通常直连不了 huggingface.co），然后在本地模型页下载“快速语音识别”（713 MB）。做完把代理打开。
- **应看到**：日志里是 `models: system proxy https none`；进度约 10 秒后才开始走（先连 huggingface.co 超时，再换 hf-mirror.com，之后一直用镜像）；下载完成并校验通过。每个文件都按 SHA-256 校验，从镜像下载一样可信。
- **不对时看**：卡片上的错误文字：“下载失败。请检查网络连接后重试。”说明两处都连不上。

**1.5 本地模型页**
- **做**：
  1. 引导先关掉（右上角 ×），打开本地模型页。
  2. 把其余的模型装进来（mac-air 上不下载，用常驻副本的 APFS 克隆，然后重启 VoxtNew）：
     ```sh
     M=~/Library/Application\ Support/VoxtNew/models
     for id in asr.fast llm.fast llm.translate; do [ -e "$M/$id" ] || cp -Rc ~/voxtnew-models/$id "$M/"; done
     ```
  3. 看每张卡片；在“快速语言模型”上点“删除”，先点“取消”，再点一次“删除”并确认。然后把它装回来（再执行一次第 2 步的命令并重启，或者点“下载”）。
- **应看到**：
  - 两节：“语音识别”和“语言模型”。推荐的两个带“默认”标签。每张卡片有名字、擅长什么、语言（地球图标）和大小：没装的是“需下载 x”，装好的是“已安装”和“占用 x”。
  - Silero（声音检测）不单独列出。
  - 删除前弹出确认：“删除快速语言模型？”“将释放 1.7 GB。之后可以重新下载。”取消什么都不删；确认后卡片回到“需下载 1.7 GB”，文件夹不见了。
  - 设置 → 存储 的“模型文件夹”一行是 `~/.cache/huggingface/hub`，“由所有 ActNow app 共用”；下面“仅 VoxtNew”和“与其他 ActNow app 共享”两项加起来和装的模型对得上。没有装别的 ActNow app 时不写“由所有 ActNow app 共用”，只有一行“VoxtNew 使用”；“网络…”对话框里也没有“应用于所有 ActNow app”那一行。
- **不对时看**：`ls -la ~/Library/Application\ Support/VoxtNew/models/`（装好的模型文件夹里有 `.voxtnew-model.json`）。

**1.5b 与其他 ActNow app 共用模型**（需要装了 AudioSmith 或 Dicta；没有就跳过）
- **做**：
  1. 在 AudioSmith（或 Dicta）里装上“快速语音识别”用的同一个模型（Qwen3-ASR 0.6B），回到 VoxtNew。
  2. 在 VoxtNew 的“快速语音识别”上点“删除”，先点“取消”；再点“删除”→“从 VoxtNew 移除”。
  3. 再点“删除”→“为所有 app 删除…”→“删除”。回到 AudioSmith 看它的模型页。
  4. 让 AudioSmith 开始下载一个 VoxtNew 也有的模型，同时看 VoxtNew 的本地模型页；下载时在 VoxtNew 里删除它。
  5. 本地模型页右上角点“网络…”：选“自定义”，填 `ftp://x` 点“保存”；改成 `http://127.0.0.1:7897` 保存；再打开，点“仅为此 app 单独设置”，选“不使用代理”保存。终端里 `open voxtnew://models/network`。
- **应看到**：
  - 第 1 步后卡片写“与 AudioSmith 共用”。装了 Dicta 的 Qwen3 4B / Gemma 4 E4B 时，语言模型里多一张“由 Dicta 安装”的卡片，只有“使用它”，没有“下载”。
  - 第 2 步弹“从 VoxtNew 移除“快速语音识别”？”“AudioSmith 也在使用这个模型，文件（712.8 MB）会保留在这台 Mac 上。”；移除后提示文件为 AudioSmith 保留，`ls ~/.cache/huggingface/hub/models--mlx-community--Qwen3-ASR-0.6B-4bit/snapshots/` 还在。
  - 第 3 步再确认一次“AudioSmith 再次使用时需要重新下载（712.8 MB）。”；删除后文件夹不见了，AudioSmith 的模型页显示“已在 VoxtNew 中删除 · 重新下载”。
  - 第 4 步卡片写“正在由 AudioSmith 下载…”，“下载”按钮是灰的，下完后自动变成“已安装”；下载时删除提示“AudioSmith 正在下载或使用这个模型，请稍后再试。”。
  - 第 5 步：`ftp://x` 不保存，提示要以 http://、https:// 或 socks5:// 开头；保存后 AudioSmith 的代理设置也变了（跟随家族）；单独设置后行下写“此设置只用于 VoxtNew。”，AudioSmith 的不变；深链打开本地模型页和这个对话框。
- **不对时看**：`cat ~/Library/Application\ Support/ActNow/models/claims/*.json`（谁声明了哪个模型）、`~/Library/Application\ Support/ActNow/models/removed.json`（墓碑）、`~/Library/Application\ Support/ActNow/settings.json`（家族的代理和下载源）。

**1.6 引导的其余几步**
- **做**：重新打开引导（首页右上角“设置引导”，或 设置 → 通用 →“打开设置引导”），翻到“试一试转录”。
  1. 先不录音，看“继续”。
  2. 按右 ⌥ 读示例句（中文界面：“嗯，那个设计评审改到周四下午，不对，周五上午，议程我今晚发出来。”），再按右 ⌥。
  3. 结果出来以后点“继续”，到“试一试翻译”：点“翻译这段文字”，等结果出来；再按 ⌃ 右 ⌥（转写的快捷键）。
  4. 点“继续”，到“试一试转写”：按 ⌃ 右 ⌥，说“写一条短消息说我会晚到十分钟”，在识别中途点右上角 × 关掉引导。
  5. 再打开引导，翻到最后一步，点“打开词典”。
- **应看到**：
  - 第 1 步：没有成功试过之前，“继续”是灰的，只能“跳过这一步”；录音和识别期间“上一步”“跳过”都不能点。
  - 第 2 步：第一次用模型要冷启动：语音识别服务约 1 秒内就绪（日志 `omni: asr.accurate ready on 127.0.0.1:… after …`），语言模型第一次加载约 1 秒，整次大约 5–7 秒；结果显示在引导里：口头语（嗯、那个）去掉了，改口后只留周五上午。出现绿色的“成功了”，顶部的“转录”前面打勾。
  - 第 3 步：译文显示在引导里；按 ⌃ 右 ⌥ 只出现“刚才按的是转写的快捷键：这一步试的是翻译（右 ⌥ ⇧）”，不会开始录音。
  - 第 4 步：关掉引导会取消这次录音（浮窗不出现、什么都不插入、历史里没有）。
  - 第 5 步：引导关闭，跳到词典页；之后重启 app，引导不会自己弹出。
- **不对时看**：日志面板里 `session` 的行（每次试用的 id 和结束状态）。

## 2. 转录（约 10 分钟）

热键默认值（ActNow 家族分给 VoxtNew 的一套，fn 留给 Auralink）：转录右 ⌥（单按右边的 Option 键），翻译右 ⌥ ⇧，转写 ⌃ 右 ⌥，粘贴最近结果 ⌃⌥V；都是点按触发。左边的 Option 不触发。这一节用默认的模型：精准语音识别 + 均衡语言模型（转录页 → 模型，两项都是“自动”）。

**2.1 基本流程：实时文字和最终结果**
- **做**：
  1. 在 TextEdit 里点一下，先复制一段别的文字，用来检查剪贴板会不会恢复。
  2. 按右 ⌥，说一句中英混合的话，例如“嗯，今天下午三点开会，讨论 VoxtNew 的发布计划，然后 please send the notes to the team”，再按右 ⌥。
- **应看到**：
  - 按下右 ⌥ 时响一声（Pop），浮窗出现在屏幕下方，不抢焦点：只有功能图标和波形（没有按钮、默认没有计时），说话时波形起伏，不说话时 bar 轻微地呼吸。
  - **实时文字**：开始说话后很快（mac-air 上第一段文字约 0.15 秒后）浮窗长出一行文字，跟着说的话更新；这是预览，最后插入的以停止后的最终识别为准。
  - 停止录音时再响一声（Tink）；按 Esc 取消时不响。停止后波形换成五个点的 loader（识别中、整理中）。最终识别在停止后约 0.7 秒（精准）出来，整理约 2–3 秒（均衡语言模型），文字插入后浮窗很快淡出。
  - 插入的是整理后的文字：“嗯”去掉，标点整齐。按 ⌘V 粘出来的还是第 1 步复制的那段文字，说明剪贴板已经恢复。
  - 历史详情：“语音识别”是精准语音识别，“语言模型”是均衡语言模型，耗时里识别和语言模型各一项。
- **不对时看**：
  - 浮窗没出现：`helper.log` 里有没有 hotkey 事件，权限页的辅助功能是否打开。
  - 浮窗提示“语音识别模型未安装。”：本地模型页。
  - 没有插入：历史详情的“交付方式”。

**2.2 整理开关**
- **做**：
  1. 转录页 → 整理，关掉“用语言模型整理”。退出 VoxtNew 再打开（让语言模型进程不在运行），转录一次，带上“嗯”“那个”。
  2. 在终端执行 `pgrep -fl voxtnew-llm`。
  3. 把开关打开，再转录一次。
- **应看到**：
  - 第 1 步：插入的是识别原文（口头语还在），停止后几乎马上插入；页面上写着“整理已关闭：不会发送任何内容给语言模型。”
  - 第 2 步：没有 `voxtnew-llm` 进程：整理关着时根本不打开语言模型。
  - 第 3 步：又是整理后的文字；`voxtnew-llm` 出现。
- **不对时看**：历史详情（关着时没有“语言模型”一项和它的耗时）。

**2.3 换成快速的模型**
- **做**：在转录页 → 模型，“语音识别”选“快速语音识别”，“语言模型”选“快速语言模型”，转录两次；然后两项都改回“自动”。
- **应看到**：
  - 下拉里没有“翻译专用模型”（它只给翻译用）。“自动”一项写着它现在会用哪个（“自动：精准语音识别”）。
  - 第一次换模型要冷启动（快速语音识别约 0.7 秒），第二次明显更快：识别约 0.2 秒，整理约 1.2 秒。
  - `pgrep -fl qwen3_asr_server` 里同一时间只有一个语音识别模型（另一个用完就停），外加一个 `vad.silero`。
- **不对时看**：日志面板（来源 omni）：`… stopped: …`、`… ready on …`。

**2.4 各种输入框**
- **做**：在备忘录、Slack、Chrome 网页里的 textarea、Chrome 里的富文本编辑器（Google Docs 或 Notion）里，各转录一次。
- **应看到**：每一处都直接插入，不会弹出答案卡片。contenteditable 的编辑器也一样。
- **不对时看**：历史详情的交付方式，和 `helper.log` 里 `textio.focus` 返回的 role。

**2.5 取消和停止**
- **做**：
  1. 录音时按 Esc。
  2. 再录一次，按住右 ⌥ 说话再松开（长按触发的快捷键）；或者再按一次右 ⌥。
  3. 连续两次快速转录：第一次插入后马上再按右 ⌥。
- **应看到**：
  - Esc 取消：什么都不插入，也不写历史，浮窗立刻消失。
  - 松开和再按一次都是停止。
  - 第二次的浮窗不会被第一次的淡出藏掉。

**2.6 浮窗外观**
- **做**：分别在白色网页（或 TextEdit）和深色窗口（终端、深色模式的编辑器）上方转录一次，录音时多停顿几秒。再在 设置 → 浮窗样式 打开“显示录音时长”录一次。
- **应看到**：
  - 浮窗是半透明的深色，背后的内容模糊地透出来；浅色和深色背景上图标、波形和文字都清楚。阴影很淡、四周完整，底部不被裁掉；圆角处模糊和深色底对齐，没有方形的边或缝。
  - 小胶囊里图标左边的留白和波形右边的留白一样宽，图标和波形上下居中对齐（和 Voxt 一样，148×48）。打开“显示录音时长”后，波形右边多一个计时，整行仍然居中。
  - 说一段长话：浮窗从小胶囊长高成“波形 + 一行实时文字”，只向上和两侧长大，底边和左右中心不动，不闪；宽度跟着文字走（文字两侧各留 20），最宽 300；文字超出后向左滚，始终显示最新的末尾，左边缘渐隐。
  - 紧接着再按一次右 ⌥：浮窗又是小胶囊（148×48），没有上一次的文字。
  - 录音时鼠标能点到浮窗下面的东西；出错提示上的 › 能点。
- **不对时看**：截图发回来（带背景）。自动的视觉回归见 10.5。

**2.7 目标不能输入**
- **做**：把焦点放在访达的文件列表或桌面上，然后转录。在弹出的答案卡片上点“复制”，再点“插入”。
- **应看到**：
  - 结果进入答案卡片：卡片和文字一样高，没有空白；鼠标停在“插入”（笔）上时 tooltip 说明访达里没有可输入的位置。
  - 点“复制”后卡片不关，图标变成勾，约 2 秒后恢复。
  - 点“插入”时卡片先消失；插不进去时卡片回来，正文下面一行小字写着原因。
  - 点卡片上的按钮时，焦点不会被抢到卡片上。卡片不能拖动。
- **不对时看**：`helper.log` 的 focus 结果。

**2.8 中途切换 App**
- **做**：
  1. 在 TextEdit 里开始录音，录音中切到备忘录，点进一条备忘录的正文，停止录音。
  2. 在 TextEdit 里开始录音，录音中切到访达，点一下桌面（不选任何输入框），停止录音。然后点进 TextEdit 的正文，在卡片里点“插入”。
  3. 在 Safari 打开一个有密码框的登录页（不要输入真实密码），在 TextEdit 里开始录音，录音中切到 Safari 点进密码框，停止录音。
  4. 给 TextEdit 建一个应用增强分组，自动按键设成 Return；在 TextEdit 里开始转录，录音中切到备忘录的正文，停止。
  5. 在 TextEdit 里选中一段文字，按翻译快捷键（“在卡片中显示结果”关闭），马上切到备忘录的正文。
  6. 在 TextEdit 里开始录音，录音中点一下 VoxtNew 的主窗口（例如设置页），停止录音。
- **应看到**：
  - 第 1 步：文字插进备忘录（停止时在前台、有输入框的 App），不弹卡片，TextEdit 不会被切回前台；历史里这条的 App 仍是 TextEdit（开始录音的 App），详情的“交付方式”写“已插入到 备忘录”。
  - 第 2 步：结果进卡片，“插入”的 tooltip 说“没有选中输入框”；点进 TextEdit 后点“插入”，文字插进 TextEdit，历史详情的“交付方式”写“已插入”。（改为点进备忘录的正文再“插入”时，文字进备忘录，详情写“已插入到 备忘录”，App 仍是 TextEdit。）
  - 第 3 步：密码框里什么都没有输入，结果进卡片，tooltip 说是密码框。
  - 第 4 步：文字插进备忘录，但不按 Return（自动按键只在开始录音的 App 里按）；在 TextEdit 里不切换时，插入后照常按 Return。
  - 第 5 步：译文不会替换到备忘录里，进卡片，tooltip 说 TextEdit 已经不在前台。
  - 第 6 步：TextEdit 回到前台，文字插进 TextEdit（不会插进 VoxtNew 自己的输入框）。
- **不对时看**：日志里 `inserted into … not …`（换了 App）或 `not inserted (…; … in front)`，以及 `helper.log` 的 focus 结果。

**2.8a 粘贴后检查：没进去的文字不会静默丢掉**（10-20，#25）
- **准备**：在 Safari（或你平时不用的浏览器窗口）打开一个本地页面，有一个 `<textarea>`、一个 `contenteditable` 的 div，再有一个拦截粘贴的输入框（`<textarea onpaste="event.preventDefault()">`）。先复制一段别的文字。
- **做**：
  1. 点进 textarea，转录一句话。
  2. 点进 contenteditable，转录一句话。
  3. 点进拦截粘贴的输入框，转录一句话。
  4. 打开终端，菜单“终端 → 安全键盘输入”打勾，回到页面的 textarea 转录一句话；做完把“安全键盘输入”关掉。
  5. 在 Arc（用户平时出问题的地方）的网页输入框里各转录几次，中途切换窗口、标签页，结束时点回输入框。
- **应看到**：
  - 第 1、2 步：文字插入，浮窗淡出；按 ⌘V 粘出的仍是准备时复制的文字（剪贴板已恢复）。日志 `delivery: focus AXTextArea in Safari (…); ⌘V posted, check inserted after N ms (AXTextArea: value a → value b…), clipboard restored`，N 一般在 200 ms 以内。
  - 第 3 步：输入框里没有文字，结果进答案卡片，正文下面一行小字“文字没有出现在输入位置：已放到剪贴板，按 ⌘V 粘贴。”；在别处按 ⌘V 粘出的是这次的结果；历史详情的交付方式是“卡片”；日志里 `check unchanged after 1000 ms`，以及一行 warning `pasted into …, but the text did not show there (unconfirmed)`。
  - 第 4 步：如果文字照常插入，记下来（说明安全输入不拦截 ⌘V）；如果没插入，卡片小字说另一个 App 开着安全输入，日志有 `secure input on (Terminal, pid …)`。
  - 第 5 步：要么插入（`check inserted`），要么进卡片并说明；不会再出现“历史里有、输入框里没有、什么提示都没有”。如果出现，把那几次的 `delivery:` 日志行发回来（focus 的角色、value、check 结果都在里面）。
- **不对时看**：`voxtnew.log` 的 `delivery:` 行；卡片多出来但文字其实进去了时，看 check 是不是 `unchanged`、before/after 的 value 是否相同（这个 App 的辅助功能值没有及时更新）。

**2.9 粘贴最近结果**
- **做**：按 ⌃⌥V。然后退出 VoxtNew（菜单栏 → 退出），重新打开，再按一次 ⌃⌥V。
- **应看到**：两次都粘出最近一次转录的结果。重启后的结果是从历史里读的，不需要模型。

**2.10 菜单栏**
- **做**：
  1. 在 TextEdit 里点一下，然后点菜单栏图标 →“开始转录”，说一句话，再点“停止转录”。
  2. 再打开菜单栏图标的菜单，把鼠标停在“最近结果”下面的第一条上，再点它，然后在 TextEdit 里按 ⌘V。
- **应看到**：
  - 开始后，菜单项变成“停止转录”；录音期间菜单栏图标变成“波形加一个实心圆点”，结束后恢复。
  - 文字插入 TextEdit，也就是点菜单之前在前台的 App。
  - 菜单里列出最近 3 条结果，每条只有一行短预览（约 13 个汉字或 26 个字母，末尾“…”）；鼠标停住时 tooltip 显示全文；点一条会复制它的全文。
  - 菜单里还有“粘贴最近结果”“打开 VoxtNew”“设置…”“退出 VoxtNew”；带更新源的构建（发布版）还有“检查更新…”。

**2.11 试一试**
- **做**：在转录页的“试一试”点“开始”录一次；再在转录页直接按右 ⌥ 录一次（VoxtNew 在前台）。
- **应看到**：两次的结果、原文和各阶段耗时都显示在页面里，不会粘贴到 VoxtNew 自己的输入框；不弹浮窗，也不写历史。

**2.12 〔可选〕长段口述**
- **做**：连续说 1 分钟以上，中英文整句交替（先说一句英文，再说一句中文……），再停止。
- **应看到**：
  - 实时文字一直跟着走；停止后要多等一会儿：最终识别会把整段重新识别一遍（100 秒的口述在精准语音识别上约 8.6 秒）。
  - 整理分段进行（每换一种语言、或每 300 字左右一段）：浮窗那一行先显示整理好的第一段，再一段段接上；日志里有 “cleaning up N characters in M pieces”。
  - 中文句子还是中文，英文句子还是英文（整段整理时，均衡语言模型会把它全翻成英文，[eval.md](eval.md)）。
  - 某一段失败（超时等）时，这一段用识别原文，其余段照常整理，浮窗出警告。
- **不对时看**：历史详情的识别原文和结果；日志里每段的警告。

**2.13 〔可选〕右 ⌘ 长按**
- **做**：在转录页把快捷键改成“右 ⌘、长按”。按住右 ⌘ 说话，松开，然后把快捷键改回右 ⌥ 点按。
- **应看到**：按下就开始录音，松开就停止。

**2.14 与 Auralink 同时运行**
- **做**：Auralink 和 VoxtNew 都打开，都有辅助功能权限，快捷键都是默认值。在 TextEdit 里：单按 fn，说一句，再按 fn；单按右 ⌥，说一句，再按右 ⌥；按住左 ⌥ 打几个字（⌥E 再按 E 是 é）；按住右 ⌥ 打同样的字；⌥ 点按 Dock 里的图标；最后按 ⌃⌥V 和 ⌃⌘V。
- **应看到**：fn 只让 Auralink 录音、插入，VoxtNew 没有反应；右 ⌥ 只让 VoxtNew 录音、插入，Auralink 没有反应；两边插入的文字各插各的（一个 app 的 ⌘V 不会让另一个 app 开始什么）。左 ⌥、按住右 ⌥ 打字都照常出 é，不触发任何一个；⌥ 点按不触发。⌃⌥V 粘贴 VoxtNew 的上一条，⌃⌘V 粘贴 Auralink 的上一条。
- **自动的部分**：`scripts/mac-hotkey-coexist.sh` 在 Auralink 运行时，用合成的按键（真实键盘的标志位）检查 VoxtNew 辅助进程的事件 tap：右 ⌥ 三个组合各触发 VoxtNew 的一个功能、Auralink 的日志里没有新的快捷键记录；左 ⌥ 不触发；fn（带 Auralink 自己的标记，免得真的让 Auralink 开始录音）VoxtNew 不触发也不吞；带 "VOXT" 标记的右 ⌥ 被放过、带 "AURA" 标记的 ⌃⌥V 照常触发并被吞掉；修饰键事件一个都不吞（排在所有 tap 最后的一个 tap 都看得到）。不录音、不粘贴、不打字：
  ```sh
  MAC_DIR=code/VoxtNew-xyz scripts/mac.sh 'scripts/build-helper.sh && VOXTNEW_COEXIST_OK=1 scripts/mac-hotkey-coexist.sh resources/darwin-arm64/helper/voxtnew-helper'   # 或者一个编好的 VoxtNew.app
  ```
  2026-10-17 在 mac-air 上（用旧 Team RY2TQTYSKQ 签名的发布式构建，10-19 起改用 779M533DL5，Auralink 在跑）：8 项全部通过，tap 回调最长 160 µs。真的按 fn 让 Auralink 录音、两边真的粘贴没有自动做：会在用户正在用的 Mac 上录音、往前台 App 里粘贴。

**2.15 长口述（约 8 分钟）**
- **做**：在 TextEdit 里转录，连续说 4–5 分钟（可以念一段文章，句子之间正常停顿），然后停止。打开 日志，看 `omni` 的行。
- **应看到**：说到 1 分钟以后，日志里每隔约半分钟出现一行 `piece N of the recording, … of audio …`；停止后几秒内文字就插入（不是等几十秒），日志有 `Final of …: N pieces while it recorded (…), the rest (…) in …`。说话时浮窗的实时文字偶尔停几秒是正常的（分段和预览共用模型）。1 分钟以内的口述没有 `piece` 行，和以前一样。
- **兜底**：`kill -STOP` 识别服务（`pgrep -f qwen3_asr_server`，挑带 `Qwen3-ASR` 的那个）后马上停止录音，15 s 后 `kill -CONT` 它（或者让它被杀掉）。应看到：仍然插入了文字（实时预览里的），浮窗黄色警告“已使用实时识别的文字：完整识别失败。”，点它打开历史里这条记录并开始重试；历史里这条是完成、带错误、有录音。

## 3. 翻译（约 8 分钟）

**3.1 选中文字的翻译（均衡语言模型）**
- **做**：在 TextEdit 里选中一段英文，按右 ⌥ ⇧。
- **应看到**：
  - 浮窗显示“正在翻译选中的文字…”和流式草稿。
  - 不录音：菜单栏不出现麦克风的橙点。
  - 译文替换选中的文字（mac-air 上一两句约 2–3 秒），剪贴板恢复。
- **不对时看**：`helper.log` 里 `textio.selection` 的结果（AX 读到的，还是 ⌘C 读到的）。

**3.2 翻译专用模型**
- **做**：
  1. 翻译页 → 模型 →“语言模型”选“翻译专用模型”。
  2. 选中一段中文，按右 ⌥ ⇧（目标语言是英语时）；再选一段英文翻成中文。
  3. 不选文字，按右 ⌥ ⇧，说一句带口头语和改口的中文：“嗯，明天上午九点，呃不对，十点开会”，再按右 ⌥ ⇧。
  4. 改回“自动”，再做一次第 3 步。
- **应看到**：
  - 下拉里有“翻译专用模型”（转录和转写的下拉里没有）。
  - 第 2 步：第一次要加载它（刚下载完的第一次可能要好几秒，之后约 0.7 秒），之后的译文几乎马上出来（一句话不到 1 秒）。`pgrep -fl voxtnew-llm` 仍然只有一个进程：同一时间只加载一个语言模型，换模型就换掉。
  - 第 3 步：口头语（嗯、呃）不进译文；但改口照原样翻（“9 a.m., no, 10 a.m.”一类）：翻译专用模型不整理口述。
  - 第 4 步（自动 = 均衡语言模型）：改口被理顺，只剩 10 点；要慢一些（2–4 秒）。
- **不对时看**：历史详情的“语言模型”一项；`llm.log` 里的 `model.load`。

- **应看到**：
  - 网页上的文字不能编辑：翻译过程中浮窗是胶囊，下面一行先显示选中的原文，再显示译文草稿；完成后一次切成卡片（宽 440），底边不动、不闪，不会粘到别处。
  - 换成日语后：原来的译文留着，标题旁转一个小 spinner，胶囊已经显示“日语”；译好后正文换成日文。不录音，也不会插入到网页里。
  - 下拉是独立的不激活浮窗：能正常弹出、滚动、选择；选完前台 App 还是浏览器，卡片位置不动。再点一次胶囊、按 Esc、切到别的 App，下拉都会收起（Esc 先收起下拉，再按一次才关卡片）。

## 4. 转写（约 5 分钟）

**4.1 改写选中的文字**

- **不对时看**：历史详情的指令、选中的文字和结果。

**4.2 按语音要求生成，再继续追问**
- **做**：
  1. 不选文字，按 ⌃ 右 ⌥，说“写一段两百字的自我介绍”，再按 ⌃ 右 ⌥。
  2. 卡片出现以后，再按 ⌃ 右 ⌥（或点卡片上的“继续”），说“短一点”，再按 ⌃ 右 ⌥（或点“完成”）。
  3. 再追问一次，录音时按 Esc；再按一次 Esc。
- **应看到**：
  - 生成过程中，浮窗还是胶囊，下面一行先显示指令，再显示回答草稿（最宽 300）；完成后一次切成卡片（宽 440），底边不动、不闪。卡片标题是回答的标题，标题行有“继续”。追问的回答是纯文本，没有标题。均衡语言模型约 25 字/词每秒（token），两百字要等十几秒，草稿一直在动。
  - 追问时卡片不消失，变成对话：标题位置是会动的小波形，正文是气泡（右边“你”，左边回答），识别的文字和新回答都流式出现，自动滚到最新。
  - 鼠标移到回答气泡上，右上角出现“复制”。
  - 录音时按 Esc：只取消这次追问，卡片留着；第二次 Esc 关闭卡片。

**4.3 〔可选〕快速语言模型**
- **做**：转写页 → 模型 →“语言模型”选“快速语言模型”，重复 4.1；然后改回“自动”。
- **应看到**：明显更快（约 75 token/秒），结果仍然通顺。

## 7. 模型进程：删除、崩溃、空闲卸载、退出、内存（约 20 分钟，含两段等待）

这一节一直开着终端，用 `pgrep -fl 'qwen3_asr_server|voxtnew-llm|voxtnew-helper'` 看进程。

**7.1 内存**
- **做**：转录一次（两个默认模型都加载了），打开本地模型页；再在“活动监视器”里看 `qwen3_asr_server` 和 `voxtnew-llm` 的内存。
- **应看到**：已加载的模型的卡片显示它占用的内存，和活动监视器对得上（数量级）。mac-air 的参考：均衡语言模型常驻约 3.4 GB、峰值约 4.3 GB；快速语言模型约 1.2 GB；翻译专用模型约 1.2 GB；精准语音识别约 2.5 GB。没加载的模型不显示内存。
- **不对时看**：截图卡片和活动监视器。

**7.1a 内存不足的提示**
- **做**：
  1. 退出 VoxtNew，在终端里带着变量启动它：`VOXTNEW_DEV_SHORT_OF_MEMORY=1 /Applications/VoxtNew.app/Contents/MacOS/VoxtNew`（每次语言模型的请求都当作慢、swap 当作 95% 已用）。
  2. 转录一次（转录页“用语言模型整理”打开），说两句话。
  3. 再转录一次。
  4. 用 ⌘Q 退出，按平常的方式打开 VoxtNew，再转录一次。
- **应看到**：
  - 第 2 步：文字照常插入，不比平时慢；随后浮窗出现一行警告（黄色三角）“内存不足，模型变慢：可退出不用的应用。”，一行放得下，5 秒后消失。日志面板（来源 session）一行 `the overlay said the Mac is short of memory: llm.balanced (VOXTNEW_DEV_SHORT_OF_MEMORY) transcribe_enhance first token …; memory pressure …, swap 19.0 of 20.0 GB used`。
  - 第 3 步：不再出现（每次运行最多一次）。
  - 第 4 步：不出现。没有变量时，只有请求真的慢（日志里那次请求的行带 `; slow:`）并且 swap 用了九成以上（`sysctl vm.swapusage`）才会出现。
- **不对时看**：日志面板（来源 session、llm）。

**7.2 删除正在用的模型**
- **做**：
  1. 转录一次，确认 `qwen3_asr_server … asr.accurate` 和 `voxtnew-llm` 都在运行。
  2. 在本地模型页删除“精准语音识别”（确认）。马上看 `pgrep`。
  3. 转录一次（转录页 → 模型 → 语音识别是“自动”）。
  4. 也删掉“快速语音识别”，再按右 ⌥。
  5. 删除“均衡语言模型”，转录一次；再翻译一次选中的文字。
  6. 把删掉的模型装回来（1.5 第 2 步的命令加上 `asr.accurate llm.balanced`，或者点“下载”），重启 VoxtNew。
- **应看到**：
  - 第 2 步：它的 `qwen3_asr_server` 几秒内退出（日志 `omni: asr.accurate stopped: …`），文件夹不见了；`vad.silero` 的服务可以还在。
  - 第 3 步：改用快速语音识别，正常出结果（第一次冷启动）；历史详情写的是快速语音识别。
  - 第 4 步：不录音，浮窗提示“语音识别模型未安装。”（›“打开本地模型”）；侧边栏底部出现“没有语音识别模型”的卡片，首页的就绪清单也提示。
  - 第 5 步：`voxtnew-llm` 退出（它加载的是被删的模型）；转录改用快速语言模型整理；翻译用剩下的模型中能翻译的那个（“自动”）。
  - 第 6 步：装回来以后一切照旧，卡片和提示都消失。
- **不对时看**：日志面板（来源 omni、llm）；`ls ~/Library/Application\ Support/VoxtNew/models/`（删除中的文件夹先移到 `models/.trash/`）。

**7.3 运行时崩溃：两次会话之间**
- **做**：
  1. 转录一次，让两个模型都加载。
  2. `pkill -9 qwen3_asr_server`，再转录一次。
  3. `pkill -9 voxtnew-llm`，再转录一次。
- **应看到**：
  - 每次 kill 之后的那次转录照常出结果，只是多了一次冷启动（语音识别约 1 秒，语言模型加载约 1 秒；mac-air 上整次约 5–7 秒）。用户看不到错误。
  - 日志：`omni: asr.accurate exited unexpectedly (…): it starts again at the next use`；`llm` 来源一行 voxtnew-llm 退出的错误，之后重新启动。
  - 没有残留的旧进程，新进程的 pid 不同。
- **不对时看**：日志面板；`llm.log` 的最后几行。

**7.4 运行时崩溃：会话进行中**
- **做**：
  1. 按右 ⌥，开始说一段话；说话途中在终端里 `pkill -9 qwen3_asr_server`，再说两句，按右 ⌥ 停止。
  2. 再转录一次。
  3. 在转写里不选文字，按 ⌃ 右 ⌥ 说“写一段三百字的产品介绍”，回答开始流出来时 `pkill -9 voxtnew-llm`。
  4. 再转录一次。
- **应看到**：
  - 第 1 步：实时文字停在 kill 的那一刻；停止后这次会话失败，浮窗显示“语音识别失败：语音识别模型已停止或没有响应。请稍后再试。”一类的提示，5 秒后消失；历史里记为失败。不会卡住，浮窗会消失。
  - 第 2 步：正常出结果（服务重新启动，多一次冷启动）。
  - 第 3 步：语言模型的请求会自动重试一次：进程重新启动、模型重新加载后回答从头再出来；如果重试也失败，卡片显示错误和“重试”，点“重试”就好。
  - 第 4 步：正常。
- **不对时看**：日志面板；历史详情的错误。

**7.5 空闲卸载**
- **做**：转录一次（两个模型都加载），然后不碰 VoxtNew，等 11 分钟，期间隔几分钟看一次 `pgrep -fl 'qwen3_asr_server|voxtnew-llm'`。然后再转录一次。
- **应看到**：
  - 约 5 分钟后 `voxtnew-llm` 退出（日志 `voxtnew-llm unused for 5m0s: stopping it`）。
  - 约 10 分钟后语音识别和 Silero 的 `qwen3_asr_server` 都退出（日志 `… unloaded after 10m0s unused`）。
  - `voxtnew-helper` 一直在。
  - 之后的转录照常，只是付一次冷启动（约 1 秒的语音识别加载和约 1 秒的语言模型加载；按下快捷键时就开始加载，和说话的时间重叠）。
- **不对时看**：日志面板。

**7.5a 保持模型载入（本地模型页 → 高级）**
- **做**：
  1. 本地模型页拉到底，“高级”默认收起；展开，“保持模型载入”是“自动”，ⓘ 说明立即开始、占用卡片上的内存、其他 ActNow app 仍可请 VoxtNew 释放内存。
  2. 选“5 分钟”，转录一次，然后不碰 VoxtNew 等 6 分钟，看 `pgrep -fl 'qwen3_asr_server|voxtnew-llm'`。
  3. 选“直到退出 VoxtNew”，转录一次，等 11 分钟再看一次；然后不重启 VoxtNew 改回“自动”。
  4. （有 AudioSmith 或 Dicta 时）仍是“直到退出 VoxtNew”，模型空闲满 1 分钟后，在另一个 ActNow app 里加载一个大模型，让它发出内存请求。
- **应看到**：
  - 第 2 步：约 5 分钟后语音识别、Silero 和 `voxtnew-llm` 都退出（日志 `… unloaded after 5m0s unused`、`voxtnew-llm unused for 5m0s: stopping it`）。
  - 第 3 步：11 分钟后进程都还在；`~/Library/Application Support/ActNow/runtime/dev.hehehai.voxtnew.json` 里它们的 `idleSince` 是转录结束的时间。改回“自动”后，从改的那一刻算起约 5 分钟 `voxtnew-llm` 退出、约 10 分钟语音服务退出，不需要重启。
  - 第 4 步：VoxtNew 的空闲模型被卸载（日志 `family: unloading … (idle) for another app`），设置不变；下一次转录照常（冷启动一次）。
- **不对时看**：日志面板；runtime 文件。

**7.5b 模型还没加载、麦克风启动慢时的浮窗**（10-20，#25）
- **做**：
  1. 退出 VoxtNew 再打开（模型都没载入），立刻按右 ⌥ 说一句话，看浮窗，说完停止。
  2. 在 本地模型 → 高级 把“保持模型载入”设成 5 分钟，等 5 分钟以上（模型被卸载），再转录一次。
- **应看到**：
  - 麦克风没出声音的那一小段（一般看不到，超过 0.4 秒才显示）：图标位置是带圆环的麦克风（一闪一闪、圆环向外扩散），波形灰色，下面一行“正在启动麦克风…”。这时说的话录不下来。
  - 麦克风有声音、模型还在加载：同样的麦克风动画，但波形跟着声音动，下面**没有文字**（用户 10-21）；模型好了以后出现实时文字，最后插入的文字包括加载期间说的话。
  - 停止时模型还没好：处理中的胶囊只有动画，不写“正在加载语音识别模型…”。
  - 模型已经载入时（第二次转录）什么都不显示。
- **不对时看**：日志 `recorded … (…, first audio after …)`；超过 1 秒有一行 warning `the microphone gave its first audio … after the start`；`omni: asr.accurate ready … after …`。

**7.6 退出时不留进程**
- **做**：
  1. 转录一次，`pgrep` 确认三类进程都在。用 ⌘Q 退出 VoxtNew，5 秒后再看 `pgrep -fl 'qwen3_asr_server|voxtnew-llm|voxtnew-helper'`。
  2. 重新打开，转录一次，关掉窗口（⌘W）：VoxtNew 留在菜单栏，快捷键还能用。再用菜单栏图标 →“退出 VoxtNew”退出，再看 `pgrep`。
  3. 〔可选〕重新打开，转录一次，`pkill -9 -x VoxtNew`（模拟 app 崩溃），10 秒后看 `pgrep`。
- **应看到**：第 1、2 步退出后输出为空。第 3 步：辅助进程和模型进程发现 app 没了，自己退出，输出也为空。
- **不对时看**：留下的进程的命令行（`pgrep -fl`），以及 `voxtnew.log` 的最后几行。

## 8. 出错、离线和权限（约 8 分钟）

**8.1 不说话**
- **做**：按右 ⌥，不说话，等 3 秒再按右 ⌥。
- **应看到**：浮窗显示“没有听到说话。”，不插入任何东西；历史里有一条，详情“录音”一行没有“送去识别”；日志里有 `no speech in … nothing sent to asr.accurate`（Silero 判断没有说话，一个字也没送去识别）。在 设置 → 音频 里关掉“跳过静音”再做一次：会送去识别，识别结果为空时同样提示。做完打开。

**8.2 前后停顿**
- **做**：按右 ⌥，停 3 秒再说一句话，说完停 3 秒再按右 ⌥。
- **应看到**：结果和平时一样，开头的字没有被吃掉；历史详情“录音”一行是“约 9 秒，送去识别 约 3 秒”这样的两个时长。
- **不对时看**：日志里有没有 `voice activity model: …; using the energy detector`（Silero 失败时改用能量检测）。

**8.3 语言模型没装**
- **做**：〔可以和 7.2 第 5 步合并〕三个语言模型都不在时（或者只剩翻译专用模型时）转录一次，再选中文字翻译一次、转写一次。
- **应看到**：转录照常插入识别原文，转录页写着“语言模型未安装：直接输入识别出的原文，不做润色。”；只剩翻译专用模型时，翻译能用，转写提示“语言模型未安装。”（›“打开本地模型”）。

**8.4 离线**
- **做**：
  1. 关掉 Wi-Fi（断开所有网络）。
  2. 转录、翻译（选中文字和语音各一次）、转写各一次。
  3. 在本地模型页下载一个没装的模型（或者“继续下载”一个暂停的）。
  4. 设置 → 诊断与关于 →“检查更新…”（发布版；开发构建会说“这个副本不能自动更新”）。
  5. 打开 Wi-Fi，在模型卡片上点“重试”。
- **应看到**：
  - 第 2 步：全部正常，和联网时一样：模型都在本机。
  - 第 3 步：试过几次以后卡片显示“下载失败。请检查网络连接后重试。”和“重试”；已下载的部分保留。没有卡死，app 其他部分照常。
  - 第 4 步：报告检查失败，不影响别的功能。
  - 第 5 步：下载接着原来的进度继续。
- **不对时看**：卡片的 ⓘ；日志面板。

**8.5 去掉辅助功能**
- **做**：
  1. 在系统设置里把 VoxtNew 的辅助功能关掉，回到 VoxtNew 看转录页。
  2. 按 ⌃⌥V。
  3. 按右 ⌥。
  4. 把辅助功能打开，不重启 app，再按右 ⌥。
- **应看到**：
  - 第 1 步：转录页顶部出现授权提示。
  - 第 2 步：⌃⌥V 仍然可用（这时改用系统的全局快捷键）。
  - 第 3 步：右 ⌥ 没反应。
  - 第 4 步：右 ⌥ 恢复。
- **不对时看**：`helper.log` 里 event tap 的安装记录。如果 macOS 要求退出重开，照做后在这里记一笔。

## 9. 首页、历史、设置（约 12 分钟）

  2. 第一次用（没有任何结果）时，在首页按右 ⌥ 说一句话，再按右 ⌥；然后切到历史页再回首页。

  - 打开了“保存录音”的记录，可以“在访达中显示录音”。
  - 搜索能找到对应的记录。

**9.2b 历史和首页的右键菜单**

**9.2c 历史设置（约 6 分钟，需要一个 U 盘或别的外接盘）**
- **做**：
  1. 历史页点搜索框右边的调节图标，看弹窗；打开“保存录音”，转录两次。
  2. “存储位置”点“选择…”，选外接盘上的一个空文件夹；看访达里的旧文件夹（`~/Library/Application Support/VoxtNew/audio`）和新文件夹；在历史里“在访达中显示录音”。
  3. 退出 VoxtNew，拔掉外接盘，再打开，转录一次；看历史页和弹窗。插回外接盘，再打开弹窗。
  4. “导出录音”选“全部录音”，点“导出…”选桌面上的一个文件夹；再选“仅转录”导出一次到同一个文件夹。
  5. “保留时长”从 3 个月改成 1 周（有一周前的记录时），先点“取消”，再改一次点“删除”。
  6. “恢复默认”；最后“全部删除…”并确认。
- **应看到**：
  - 第 1 步：“保存录音”和 设置 → 隐私 的“保存录音”同时变；“已保存的录音”是 2 段和大小。
  - 第 2 步：进度条走完，toast“已把 N 段录音移到 …”；旧文件夹空了，新文件夹里是 `<id>.wav`；访达选中新文件夹里的那段。
  - 第 3 步：历史页顶部提示“… 当前不可用：在它恢复之前，新录音保存在 …/audio”，新录音在默认文件夹；插回后打开弹窗，提示消失，新录音存回外接盘。
  - 第 4 步：`transcription/20261017-143005-开头几个词.wav` 这样的文件；第二次不出现重复的 `-2` 文件。
  - 第 5 步：弹出“现在删除 N 条记录？”；取消后下拉回到“3 个月”、记录都在；删除后历史页、首页、菜单栏的最近结果里都没有了，录音文件也没了。
  - 第 6 步：录音移回默认文件夹；全部删除后记录还在，详情里没有“在访达中显示录音”。
- **不对时看**：日志里 `history:` 和 `recordings:` 开头的行。

**9.2d 重试（约 5 分钟）**
- **做**：设置 → 隐私 → “保存录音”关着。按 2.15 的办法让一次转录失败（停止前 `kill -STOP` 识别服务、不要有实时文字：录音后马上停止），或者在 本地模型 把语音模型的服务杀掉后马上说一句。然后到 历史。
- **应看到**：这条记录的行上不是红色的“失败”，而是可以点的“重试”；详情里有“重试”按钮，下面写“识别失败，录音暂时保留，（7 天后的日期）后删除。”；右键菜单有“重试”。点“重试”：行上显示“识别中…”（开着整理时接着“整理中…”），完成后这一行换成新的文字，没有新增记录，没有插入任何地方，Toast 写用时；详情的“保留”说明消失，录音文件夹里这段录音被删除。
- **没有录音的失败记录**：仍是“失败”，鼠标停在上面写“没有保存录音，无法重试”；详情和菜单里都没有重试。
- **成功的记录**（打开“保存录音”后转录一次）：详情和右键菜单里是“重新识别”。
- **过期**：把一条暂时保留的录音的 `audio_until` 改成过去的时间（`sqlite3 ~/Library/Application\ Support/VoxtNew/…/voxtnew.db`，只在测试数据上）后重启 VoxtNew：录音被删除，记录还在，日志写 `deleted 1 recordings kept for a retry`。

**9.3 设置 → 音频**
- **做**：
  1. 打开 设置 → 音频，看麦克风列表；接上 AirPods（或别的麦克风）后点刷新，把它“添加”到优先列表并移到第一位。
  2. 转录一次；再断开 AirPods，回到这一节看列表，再转录一次。
  3. 关掉“播放提示音”，转录一次，再打开。
  4. 提示音预设（约 2 分钟）：“播放提示音”开着时，点它左边的下拉，用鼠标在几项上停一下，再用方向键上下移动；选“Hero”；点下拉右边的音符按钮，快速连点两次；最后选回“柔和（Pop/Tink）”。选 Hero 后转录一次。
- **应看到**：
  - 系统默认输入标着“系统默认”，优先列表里正在用的那个标着“当前录音设备”。
  - 第 2 步：第一次用 AirPods 录音；断开后它显示“未连接”，录音回到下一个设备或系统默认输入。
  - 第 3 步：关掉后开始和停止都不响；关着时开关左边没有下拉和试听按钮，打开后又出现。
  - 第 4 步：下拉列出 10 项（柔和（Pop/Tink）、Ping、Morse、Submarine、Basso、Bottle、Frog、Hero、Purr、Sosumi）；打开菜单时不响；在某一项上停约 0.3 秒会响一次它的声音，快速划过不响，只停留不会改变选择；选中一项时立即响；试听按钮在声音播放期间变成强调色，之后恢复；连点时后一次打断前一次，不会叠在一起。选 Hero 后转录时，开始和停止都是 Hero。
- **不对时看**：`helper.log` 里 `capture.started` 的 device 和 fellBack。

**9.3b 录音时静音系统声音（约 4 分钟，需要扬声器或耳机）**
- **准备**：设置 → 音频 → 声音里“录音时静音系统声音”是开着的（默认）；在浏览器里放一段有声音的视频，音量调到能听见；菜单栏的声音图标或 系统设置 → 声音 能看到输出设备是否静音。
- **做**：
  1. 视频播放时按右 ⌥ 说一句话，再按右 ⌥ 停止。
  2. 先在菜单栏把输出设备静音，再按右 ⌥ 录一句、停止。
  3. 视频播放时按右 ⌥，录音中在菜单栏取消静音（或按键盘的静音键），再停止。
  4. 视频播放时按右 ⌥ 开始录音，录音中切换输出设备（例如连上或断开 AirPods，或在菜单栏选另一个输出），再停止。
  5. 分别用翻译（右 ⌥ ⇧，不选文字）、转写（⌃ 右 ⌥）各录一次；转写的回答卡片里点“继续”再录一次追问。按右 ⌥ 开始后按 Esc 取消一次。
  6. 把输出切到一个不支持软件静音的设备（例如部分 HDMI / DisplayPort 显示器、USB 声卡）再录一次。

## 10. 自动真机测试（无界面）

在一台正在被别人用的 Mac 上也能跑（例如别的线程同时在跑测试）。从 Linux 通过 ssh 执行，全程：

- 不开窗口，不改变前台 App，不抢焦点；
- 不发按键，不装事件 tap（只调用 `hotkey.status`，不调用 `hotkey.configure`）；
- 不碰剪贴板，不做真实粘贴（文本输入输出是只记录文字的假实现，只读调用真实的 `textio.focus`）；
- 不用麦克风和扬声器，也不会弹出授权窗口：辅助进程的录音改成读取 WAV 文件（`VOXTNEW_HELPER_CAPTURE_FILE`，**仅用于测试**，见 [helper-protocol.md](helper-protocol.md) 第 4 节）。读出来的音频和麦克风走同一条链路：混成单声道、重采样、`PCMFramer`、`capture.level` 和 `capture.pcm` 通知、停止、取消和 maxSeconds 的结束方式都一样；
- 只读取已经在运行的浏览器的网址（按 pid），不启动、不激活浏览器；
- 不联网（`mac-e2e.sh` 用假的本地模型；`mac-regress.sh` 用 mac-air 上常驻的模型）；
- 占用资源少：`nice -n 10`，Swift 和 Go 都只用 2 个并行任务（`GOMAXPROCS=2`、`GOFLAGS=-p=2`），各步骤依次执行；每一步开始前检查空闲内存，低于 40%（`VOXTNEW_MIN_FREE`）就停止；结束时确认没有残留的进程。

**10.1 怎么跑**

```sh

MAC_DIR=code/VoxtNew-xyz scripts/mac.sh scripts/mac-regress.sh   # 真实模型的回归（10.6），约 5 分钟
```

单独跑某一项：`VOXTNEW_MAC_E2E=1 VOXTNEW_HELPER=<辅助进程路径> go test -run 'TestMacHelperReadOnly' -v .`（在 Mac 上执行；辅助进程用 `scripts/build-helper.sh --out DIR` 编译）。真实模型上的单项（`TestMacE2EOmni`、`TestLLM*`、`TestEval*`）的命令见 `mac_e2e_omni_test.go`、`llm_e2e_test.go` 的文件头和 [eval.md](eval.md)。

**10.3 发现过的问题**

- **Arc 的 `browser.url` 读不到网址**（`via none`，查满 400 个节点，641 ms），同一时刻 `textio.focus` 也报“没有焦点元素”。原因：Chromium 只在辅助功能客户端请求时才构建网页的 AX 树，辅助进程原来只给 Electron 应用设置 `AXManualAccessibility`。**已修复**：Go 用 `app.configure` 下发 Chromium 系浏览器名单，辅助进程在它们切到前台时设置这个属性（每个进程一次）；`browser.url` 查不到网页区域时也设置一次，150 ms 后重读（结果带 `retried`）。实测：Arc 从 `none` 变成 `ax-focus`，属性设置后一直有效（新的辅助进程第一次读 20–40 ms，之后 2–5 ms）；Chrome 没有退化。切到前台时设置这一条没法在无界面测试里触发，留给人工补测第 6 步。

**10.5 浮窗的视觉回归（约 1 分钟，有短暂的浮窗）**

`scripts/mac-overlay-check.sh` 让真正的浮窗窗口依次走过各个状态，每一步截图并记录窗口的 frame。它不是无界面的：浮窗和它下面的一块背景板会在屏幕底部（浮窗平常的位置，鼠标所在的显示器）出现约 15 秒，每个状态约 1 秒；但两者都是不激活的面板，不抢焦点、不改前台 App，也不碰剪贴板和按键。


**10.6 真实模型回归（`scripts/mac-regress.sh`，约 5 分钟，无界面）**

用 mac-air 上常驻的模型和运行时（`~/voxtnew-models/<id>/`：六个目录里的模型；`~/voxtnew-runtime/{omni,llm}/`：Omni 运行时和 voxtnew-llm；两处的 README 写了怎么更新），不下载、不编译它们。和 `mac-e2e.sh` 分开：

```sh
# 在 Linux 上执行。同步到独立目录（不要用 code/VoxtNew）
MAC_DIR=code/VoxtNew-xyz scripts/mac.sh scripts/mac-regress.sh          # 快速版
MAC_DIR=code/VoxtNew-xyz scripts/mac.sh scripts/mac-regress.sh --full   # 完整评测（多约 20 分钟），表格在 build/regress/eval
```

依次：编译辅助进程，`swift test`；`TestMacE2EOmni`（真实辅助进程读语音样本文件，两个语音模型和 Silero）；`TestLLM*`（`VOXTNEW_LLM_REAL`，三个语言模型）；评测快速版（`TestEval*`：每类一段，转写 8 例，对照下限；应用增强和词典各一个完整会话，见 [eval.md](eval.md)；`VOXTNEW_EVAL_LLM=all` 时也评借用的语言模型）；把运行时放进 app 编译（`go tool mygo build`，签名检查），再以 `VoxtNew.app/Contents/MacOS/VoxtNew --smoke <dir>` 启动：自己的数据目录、不开窗口、没有快捷键（不装事件 tap），启动打包的辅助进程，经 app 自己的 Library 让语音模型和语言模型各回答一次，然后按 app 的方式退出。每一步之后、以及最后，检查没有残留的 `qwen3_asr_server`、`voxtnew-llm`、`voxtnew-helper`。最后打印一张汇总表，退出码是失败的步骤数。不用麦克风和扬声器，不碰剪贴板和前台 App。另一个线程的 `voxtnew-llm` 或 `qwen3_asr_server` 在运行时会提示“时间不准”。

2026-10-17 第一次（mac-air，另有 AudioSmith、Dicta 和 M2b 的进程，swap 约 12 GB）：7 步里 6 步通过；`llm-real` 里 `TestLLMOpenerThroughLibrary` 因为脚本导出的 `VOXTNEW_DEV_LLM` 用上了真实模型而失败，测试已改为自己清掉这两个变量。smoke：辅助进程就绪，asr.fast 826 ms、llm.fast 2.8 s 回答，退出后没有残留进程；app 280 MB。修好后第二次：7 步全部通过，共约 4.5 分钟（omni-e2e 29 s、llm-real 65 s、评测快速版 160 s、app 编译 14 s、smoke 5 s）。

**10.7 发布式构建**

发版前用和发布一样的流程构建一次：`scripts/release.sh` 编译（或用 `--runtimes` 直接取）辅助进程、Omni 运行时和 voxtnew-llm，放进 app，`go tool mygo build` 打包签名，再由 `scripts/release-verify.sh` 检查每段代码的签名、entitlement，以及两个运行时能从 app 里启动。不设签名身份时是 ad hoc 签名、没有更新源的测试构建：

```sh
MAC_DIR=code/VoxtNew-rel scripts/mac.sh 'export PATH=/opt/homebrew/bin:$PATH; scripts/release.sh --runtimes $HOME/voxtnew-runtime'
```

Developer ID 签名、公证、发布和更新的测试见 [release.md](release.md)。用发布版（hardened runtime）至少再做一遍 10.4 的人工补测清单，确认两个运行时在签好的 app 里能加载模型（release.md §8）。
