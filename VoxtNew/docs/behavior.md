# 行为对照：Voxt 怎么做 / VoxtNew 怎么做 / 为什么

本文继承自 Auralink（VoxtNew 由它复制而来，见 NOTICE），各节标题里的 M1–M6 是 Auralink 的里程碑；VoxtNew 的里程碑见 [plan.md](plan.md)。功能和行为参考 Voxt（`hehehai/voxt` @ `baa6f31`，1.15.0），本仓的 `../Voxt` 也是它；VoxtNew 可以直接移植 Voxt 的代码（同一作者，Apache-2.0），但仍按自己的结构组织。每个模块落地时，在这里补一节对照表，作为评审依据：

- **Voxt 怎么做**：写清楚出处（源码文件或文档）。
- **VoxtNew 怎么做**：写实际实现的行为，并指向实现它的包或文件。
- **为什么**：保留的写保留理由；改掉的写改的理由。

状态：✅ 已实现　◐ 部分实现（骨架或接口已经有了）　○ 计划中（写明负责的里程碑）

## 1. 架构原则（方案 §1）

| # | Voxt 怎么做 | VoxtNew 怎么做 | 为什么 | 状态 |
|---|---|---|---|---|
| 1.1 | 会话状态分散在 `AppDelegate` 的 43 个 extension 里（`Voxt/App/*Flow.swift`、`Recording/`），取消和收尾由各个 Flow 各自处理 | 一个 `Session` 状态机（idle → recording → recognizing → composing → delivering → done/cancelled/failed）是会话唯一的所有者；所有异步回调都带 sessionID，迟到的一律丢弃 | 身份、取消、“只收尾一次”集中在一个地方，才能写表驱动测试；迟到回调不会污染下一次会话 | ✅ M3：`internal/session`（§5）；helper 的 job 通知也带 `job`，supervisor 丢弃已结束 job 的迟到通知 |
| 1.2 | 语音翻译“先增强、再翻译”，两次 LLM 请求（`docs/Prompt.zh-CN.md`“语音翻译”一节） | 一次会话最多一次 LLM 请求：Prompt Composer 按“功能 × 能力 × 场景 × 词典 × 语言”拼出一个请求 | 少一次往返，延迟和费用减半；两段式在第二段会丢掉第一段的上下文 | ✅ M3 转录、M4 翻译和转写（`internal/compose`，§5、§6）；翻译只有“看起来没翻译”时才多一次严格重试 |
| 1.3 | 命中应用增强分组时，用分组 prompt **整个替换**全局 prompt（`Core/EnhancementPromptResolver.swift`） | 分组 prompt 作为“场景层”**叠加**在基础清理之上 | 用户写的分组规则不完整时，基础清理（去口头语、标点）不会跟着丢 | ✅ M5（§7） |
| 1.4 | 规则匹配、prompt 拼接和 AppKit 调用写在一起 | 匹配、组合、热键判定、文本后处理是纯 Go 函数，Linux 上做表驱动测试；录音、事件 tap、AX、粘贴放在窄接口后面，测试换成假实现 | 不需要 Mac 也能测完整链路 | ◐ M1：helper 进程和协议、假 helper（`helpertest`）、`permission.Fake`、in-process 的假 supervisor 都已就位 |
| 1.5 | 设置保存在 UserDefaults 的几百个键里（`Voxt/` 中有 259 处 `UserDefaults`），还保留了旧版单热键之类的迁移代码 | 设置是一个带版本号的类型化文档（`internal/settings`，v1），存在 SQLite 的 `documents` 表里；不兼容、也不读取 Voxt 的键 | 从 v1 开始，没有历史包袱；整个文档可以快照、比较、重置 | ✅ M1 |
| 1.6 | 读输入框用了 CDP（`App/TextInputCDP.swift`），还有截图、窗口上下文等链路 | 不做 CDP、截图和窗口上下文 | 已废弃或小众，权限和维护成本高（方案 §2“不做”） | ✅（不实现） |

## 2. 骨架（M1）

| # | Voxt 怎么做 | VoxtNew 怎么做 | 为什么 | 状态 |
|---|---|---|---|---|
| 2.1 | SwiftUI 设置窗口和菜单栏 | AudioSmith 的外壳（Go + MyGo）：侧边栏、⌘K、设置对话框、菜单栏图标；没有底部状态栏（见 2.7） | actnow 家族统一 UI（RULES） | ✅ |
| 2.2 | 录音、热键、粘贴都在 app 主进程里 | 录音、事件 tap、AX 读写放在 Swift helper 子进程；Go 进程负责 UI、业务和网络 | MyGo 不能录音；事件 tap 的回调必须同步决定是否吞键；helper 崩溃不会带走 UI（方案 §4.1） | ✅ helper（`helper/`，Swift）和协议 1（`docs/helper-protocol.md`）已完成：录音、热键、textio、前台 App、浏览器 URL、权限 |
| 2.3 | 历史存在自己的数据库（`Core/VoxtDatabase.swift`） | SQLite（MyGo 插件）迁移 001：`history`（带 trigram FTS，覆盖原文、选中文本、口述指令、结果）、`dictionary_terms`、`documents`；迁移前自动备份，拒绝打开更新版本 app 的数据库 | 中文子串搜索可用；数据可以整体搬家（设置 → 存储） | ✅ |
| 2.4 | API Key 存在钥匙串 | 钥匙串 service "VoxtNew"，账号 `asr.<id>`、`llm.<id>`（`internal/secrets`） | 同样的做法 | ✅ |
| 2.5 | 权限说明分散在 onboarding 和各设置页 | 权限是设置对话框里的一节（设置 → 权限，在“通用”之后，`/settings/permissions`）：只有麦克风和辅助功能两行，各自说明用途并提供授权入口；首页的“打开权限”、⌘K、深链 `voxtnew://permissions` 和旧路径 `/permissions` 都打开这一节（`permissions.go`、`shell.go` 的 `movedPaths`） | 只剩两项权限，看一次就走，不值得占侧边栏的位置；浏览器网址只用辅助功能（AX）读，不需要浏览器自动化授权（用户 10-15 决定） | ✅ 状态和授权都走 helper（`permissions.*`）；helper 没起来时由 app 自己读。M5 已删除 helper 的 `automation.*`、AppleScript 和 Apple Events 声明 |
| 2.6 | 主窗口 820×560 | 主窗口默认 800×520，最小 680×440（`shell.go`；用户 10-15 两次缩小，原来是 880×580 / 720×480）；窗口记住的尺寸优先，旧版本留下的大窗口不会被缩小。按这两个尺寸排版：800 宽时显示完整侧边栏（窄于 740 才自动收成图标，见 9.9），页面宽 600；侧边栏行距收紧，520 高时一屏放得下全部页面；图标 rail 在 440 高时放得下全部图标，更矮时列表滚动，底部渐隐；模型服务卡片最小 260 宽，两种尺寸下都是两列；历史详情（290 宽，列表至少 300）和应用增强的分组列表（200 宽，右侧至少 380）在两种尺寸下都并排显示，不变成抽屉；设置对话框、引导、模型服务对话框、快捷键表的宽高都跟着窗口走，内容滚动，底部按钮始终可见 | 比 Voxt 还小一点，常驻桌面不占地方；比 AudioSmith 的 1100×720 更适合输入工具 | ✅ |
| 2.7 | 状态写在设置和菜单栏里 | 没有底部状态栏（用户 10-15）。版本号在侧边栏底部“设置”一行的右侧；通知是“设置”上方的一叠卡片（`shell_notices.go`）：最新的一张完整显示（图标、标题、一两行说明、可选的操作、右上角 ×），后面最多两张露出底边；× 关掉一张，下一张浮上来；多于一张时有“N 条通知 · 全部清除”；没有通知时什么都不显示。侧边栏收成图标时，“设置”图标上有红点，点它弹出同样的卡片（下面是“设置”入口）。卡片来自通知中心（`internal/notify`，新增 `Dismiss`），原来的铃铛、通知弹窗和未读数都去掉了。状态栏上的“ASR … · LLM …”和“辅助进程就绪”正常时不显示，出问题时变成卡片：服务没就绪（`problem/services`，带“打开模型服务”），辅助进程停了（`problem/helper`，带“重启辅助进程”）；问题解决后卡片自动消失；用户关掉的卡片，同一个问题本次运行不再出现。日志面板只留 ⇧⌘L、⌘K 命令和“日志”页 | 正常时没有要看的状态，底部 26 px 留给页面；出问题时卡片带着修复的操作，比一行状态更容易看到 | ✅ |

## 3. 模型（VoxtNew：只用本地模型）

Auralink 的这一节对照的是远程 ASR / LLM 服务（豆包、阿里百炼、OpenAI 兼容、阶跃、DeepSeek 等），VoxtNew 在 M0 删掉了整个远程层（docs/architecture.md §5），这一节随之删去。本地模型的对照（Omni 运行时的生命周期、各模型的 Final 请求策略、实时预览节奏、Silero VAD、模型目录与固定版本）在 M1–M3 落地时补在这里，出处是 Voxt 的 `OmniASRRuntime.swift` 等。

| # | Voxt 怎么做 | VoxtNew 怎么做 | 为什么 | 状态 |
|---|---|---|---|---|
| 3.1 | 模型目录很长：多个 ASR 系列、十几个 MLX LLM 和两个 GGUF，界面上写系列名、量化、评分和标签；下载时先查 Hub 的文件树，按扩展名过滤，按大小校验；模型放在自己的 `~/Library/Application Support/Voxt/model-storage/`（HF 缓存布局） | 只有六个模型（`internal/models`）：精准 / 快速语音识别、人声检测（内置，不让选，随第一个语音模型安装）、均衡 / 快速语言模型、翻译专用模型，每个钉住 ActNow 家族 pins 表里的 commit（`actnowkit/models.PinsOfApp("voxtnew")`，`TestFamilyPins`；omni 的同时与 `sglang_omni_mlx/native/ci/models.json` 一致，`TestOmniPins`），列出用到的文件和每个文件的 SHA-256（Hy-MT2 只下一个 GGUF，Qwen3.5-4B-OptiQ 不下 `optiq/`），带家族的 `family`、`quant`。**模型放在家族模型库 `$HUB`**（Hugging Face 缓存，默认 `~/.cache/huggingface/hub`，家族设置 `models.root` 优先；标准 HF 布局），与 AudioSmith、Dicta 等共用：别的 app 已经下载过的同一 `repo@commit`（如快速语音识别 = Qwen3-ASR-0.6B-4bit `313d8501`）不再下载：没有别的 app 声明的直接算 VoxtNew 已安装；别的 app 声明着的显示“由 AudioSmith 安装”，在引导的复用卡片或本地模型页点“直接使用”后（声明 origin `reused`）才归 VoxtNew 用，此后“从 VoxtNew 移除”只去掉 VoxtNew 的声明，它又回到“由 AudioSmith 安装”；运行时从 `snapshots/<commit>` 加载。另有两个**借用的**语言模型（`Borrowed`：家族的 Qwen3-4B-Instruct-2507、Gemma 4 E4B），VoxtNew 从不下载，只在别的 app 装了、用户选择使用后出现，作为均衡 / 快速模型的 `alternatives`；精准语音识别的 alternative 是快速语音识别。界面只用朴素的话说擅长什么、支持哪些语言、多大，不显示仓库、系列和量化 | 用户只需要最好的几个，参数由我们调好；固定 commit + 哈希，下载到的就是测过的那份。家族规范 v1.0.3 §7（§17 Q7 已定）：VoxtNew 不另建模型目录，与家族共用 HF 缓存，装过 AudioSmith / Dicta 的用户免下载 | ✅ M1b，家族 F1 |
| 3.2 | 断点续传（sidecar 记录），失败时换 hf-mirror.com | 下载用家族的 `actnowkit/hfhub`（不得拷 AudioSmith AGPL 时期的代码）：先向 Hub 的 API 取文件清单（LFS 文件的 SHA-256 必须与目录一致，其他文件按 git blob id 校验），huggingface.co 与 hf-mirror.com 赛跑、胜者用一天；大文件分段并发、`blobs/<blob>.incomplete` + `.incomplete.parts` 续传（也能接手别的 app 的半截下载）；全部校验通过才链接 snapshot（先建在 `<commit>.incomplete` 再改名）并写 `refs/main`；下载期间持有家族的 repo 共享锁和 blob 锁（与 huggingface_hub 同一路径）：另一个 app 正在下同一个 blob 时等它（显示“正在由 AudioSmith 下载…”），完成后跳过；下完自动写 VoxtNew 的声明（`models/claims/dev.hehehai.voxtnew.json`）。开始前留 2 GB 空闲（hfhub 默认）。取消保留已下载的部分。**网络跟随家族设置**（规范 §9）：`network.proxy`（"" 自动 = 环境变量里的代理，否则 macOS 系统代理（M4 的 CFNetwork 读取，5 s 读一次，遵守例外列表）；`direct`；或代理 URL）和 `network.hfEndpoints`（自动赛跑 / 只用官方 / 只用镜像 / URL 列表），在本地模型页的“网络…”里改，默认跟随家族（应用于所有 ActNow app），可以“仅为此 app 单独设置”；`HF_ENDPOINT` 环境变量优先 | 断在哪里都不会留下半个模型；两个 app 同时下载同一个模型只有一份流量（规范 §7.4、§16.1 场景 3）。mac-air 直连 huggingface.co 超时、hf-mirror.com 可用；从界面启动的 app 拿不到 https_proxy，只能通过系统代理连上 huggingface.co（M4 实测）。M0 删掉的“设置 → 网络”不恢复整页：代理和下载源是家族共享的，只在下载模型时用 | ✅ M1b，系统代理 M4，家族 F1 |
| 3.3 | 无 | 删除按家族规则（规范 §7.6）：先问 `store.Decide`；没有别的 app 声明、也没有在运行的 app 加载着它，就删掉 snapshot 和不再被引用的 blob；有别的 app 在用时弹窗“从 VoxtNew 移除”（默认，只去掉 VoxtNew 的声明，文件留下）或“为所有 app 删除…”（再确认一次；删文件并写墓碑，其他 app 读到后去掉自己的声明，显示“已在 VoxtNew 中删除”）；别的 app 正在下载时立即提示稍后再试，不排队。删除前仍先让运行时卸载它（`local.Openers.Unload`）。启动时和收到家族的 models 通知时应用墓碑（`store.ApplyTombstones`）。原来的开发选项 `VOXTNEW_HF_CACHE`（从 HF 缓存硬链接）去掉了：模型本来就在 HF 缓存里 | 删除不误伤别的 app 的模型（规范 §16.1 场景 2）；拿不准就不删 | ✅ 家族 F1 |
| 3.4 | 翻译专用的 GGUF 模型只在翻译里出现 | 同样：翻译专用模型只服务“翻译”（`local.Model.Features`），转录清理和转写选不到它，“自动”也不会落到它 | 它只会翻译 | ✅ M1b |

## 5. 会话与转录（M3）

| # | Voxt 怎么做 | VoxtNew 怎么做 | 为什么 | 状态 |

| 5.1 | 会话身份和收尾在 `RecordingSessionLifecycle` 里，录音、识别、增强、交付、历史分散在各个 Flow 扩展（`App/Recording/*`、`SessionTextIO.swift`）里，靠 `activeRecordingSessionID` 比对丢弃过期回调 | `session.Manager` 一次只跑一个会话，一个 goroutine 按顺序走完 录音 → 识别 → 整理 → 交付 → 历史；每个回调先过 `Manager.update`：不是当前会话、或者已经收尾，就丢弃；`end` 只生效一次。快照带递增的 `Rev`，UI 只收更新的 | 一个所有者、一个顺序，Linux 上能用假实现把每条路径（取消、超时、迟到回调）都测到（`internal/session` 的表驱动测试） | ✅ |
