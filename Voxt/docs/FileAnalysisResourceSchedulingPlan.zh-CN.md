# 文件任务分析：资源调度、阶段释放与断点恢复方案

> 状态：方案已按用户确认的产品取舍制定；P1 的文件 ASR 资源等待与任务级等待 UI 原型、P2 的 ASR 窗口级检查点和 ASR 阶段边界释放原型已实施，完整恢复稳定期和说话人阶段恢复仍未实施。
> 基线：`feat/file-preprocessing-resource-safety`，已有流式预处理及临时诊断日志；以实施开始时的实际提交和依赖版本为准。
> 范围：预处理完成后的文件转录、说话人分析及结果交付。不是重新设计预处理，不改变实时会议的默认行为。
> 性能原则：以下资源收益是优化目标，不是已测量结果。现有日志能定位本次失败，但不能证明系统内存压力的具体来源。

## 1. 已确认的产品决策

| 决策 | 用户选择 | 对实施的约束 |
| --- | --- | --- |
| 规划范围 | 完整分期方案 | 覆盖暂停恢复、模型生命周期、检查点及后续性能优化 |
| 资源长期不足 | 保持暂停 | 不因等待时长自动失败；资源恢复稳定后自动继续；用户始终可以取消 |
| 默认取舍 | 资源优先 | 单文件重工作、单重型本地推理；必要时接受重载耗时以降低驻留与峰值 |
| 部分结果 | 允许查看，明确未完成 | 转录阶段完成即可查看；说话人未完成时不得伪装为完整成功 |

本方案采用上述默认值，不再增加“速度优先／高并发”配置入口。下文恢复观察期等参数是初始工程建议，需通过测试调整，不作为用户承诺。

## 2. 事实与问题边界

### 2.1 已确认的失败链

用户 2026-09-20 提供的日志中，标准化音频长约 7252.52 秒。结合此前同一任务日志：预处理约 13.87 秒，归档副本复制约 1.63 秒，随后成功执行了多个 ASR 窗口。

最终在任务运行 768.66 秒、完成前 5880 秒音频时，第 99/121 个窗口的首块（5880–5902 秒）出现：

```text
inference-permit-requested: memoryPressure=true
→ Local inference admission rejected: workClass=fileASR, reason=memory-pressure
→ strict ASR chunk failed
→ pipeline-stopped: stage=transcribing
→ task-failed
```

此前累计 333 个片段。该次失败在下一块推理准入时发生，不是该块模型执行崩溃；没有进入说话人分析。附件覆盖区间的进程 RSS 采样约 307–325 MB，温度状态为 nominal/fair。不能因此断言没有系统内存压力，不能将 RSS 等同统一内存总占用，也不能将系统 XProtect 消息直接当作失败根因。

### 2.2 当前代码中值得调整的结构

- `MeetingLocalInferenceCoordinator.acquire` 把可暂缓工作在内存/温度压力下直接拒绝；文件严格转录向上传递错误，终止整条任务。
- 准入与排队后执行使用不同条件：`canRun` 检查录音和内存，但未统一检查温度；只有修改首次准入不足以形成完整保护。
- `MeetingImportedFilePipeline` 原先在整个流水线期间持有 ASR active-use，包括后续说话人分析；当前原型已在 ASR 完成后结束 lease 并请求释放闲置 ASR 模型，但真实 physical footprint 回收仍需 macOS 验收。串行推理不代表模型一定不会同时驻留。
- Sortformer 的共享引擎保留模型，当前未提供明确的阶段卸载入口；其跨窗口 streaming state 又不能任意重置。
- ASR 每次最多读 60 秒，但 `chunks(for:)` 提前复制当前窗口的多个音频块；结果数组持续积累，失败后没有文件任务专属的块级恢复。
- 文件说话人流程未使用已有的 `analyzedSegmentsPreservingStructuredSpeakerData` 入口；MOSS 的原生标签可能被重复处理，但跨窗口标签身份仍须验证。
- 标准化 WAV 在分析前复制一整份，只是为了满足后续历史导入移动文件的所有权约定。
- 每块识别仍解析部分设置和词典信息；文件任务不应随用户切换前台应用或修改设置而悄悄改变处理口径。
- 文件任务复用会议协调器的 `isActive`，且开启新会议时会拒绝正在分析的文件。不能仅增加暂停状态就宣称已支持前台录音抢占。

## 3. 目标架构与不做事项

```text
现有流式预处理 → 校验通过的只读音频缓存
                      ↓
              固定任务配置与输入身份
                      ↓
 ASR：资源准入 → 按需读取一个工作单元 → 推理 → 原子提交结果/游标
                      ↓
           转录阶段完成，可查看未完成结果
                      ↓
       释放 ASR 阶段资源，重新检查设备预算
                      ↓
 说话人分析：保持连续状态 → 窗口边界让出许可 → 提交完整阶段结果
                      ↓
            按需创建独立历史音频归档
                      ↓
             幂等保存最终历史与任务状态
```

资源不足时走“停新工作 → 安全边界提交 → 释放能释放的资源 → 等待 → 稳定后重新准入”，而不是终止或不停重试模型。

保留：标准化缓存、原始时间轴、分阶段串行分析、当前输入/时长/磁盘安全上限。允许 ASR 和说话人分两遍有界读取音频，以换取不同时驻留不必要模型。

本轮不做：默认并行 ASR/说话人、整文件 PCM/张量、额外有损压缩、默认降噪/人声提取、直接拼接删除静音、自动切远程服务或更小模型、未经验证提高 4 GiB 准入上限。摘要仍使用现有模型配置与用户策略，不默认纳入文件分析的并行推理。

## 4. 错误分类与处理方案

错误处理先判断“是否还能安全继续”，再决定任务状态；不能用 `localizedDescription` 或某个非空错误统一归类。错误类别需要结构化保存/日志化，用户文案与诊断详情分离。

| 类别 | 典型来源 | 自动动作 | 任务状态 | 是否保留已完成结果 |
| --- | --- | --- | --- | --- |
| 暂时资源不足 | memory warning/critical、thermal serious/critical、录音占用、推理通道暂忙 | 不读取下一块、不占推理许可；按恢复事件/退避重试；必要时释放窗口和闲置模型 | 等待系统资源 | 是 |
| 用户可修复资源 | 磁盘空间不足、缓存目录不可写、模型未下载、权限/安全作用域失效 | 停止继续写入；不自动无限重试；显示动作和重试入口 | 需要处理 | 是 |
| 输入/格式错误 | 源文件被删除或改变、WAV 缓存损坏、无音轨、解码器拒绝媒体 | 保留原文件和有效缓存；使当前阶段失败；禁止跳过损坏块 | 失败，可重试 | 是 |
| 模型/推理错误 | 模型加载失败、单块推理异常、依赖 API 错误 | 记录模型/阶段/音频块；同一输入最多一次有限重试；再次失败停止当前阶段 | 失败，可重试 | 是 |
| 持久化错误 | 结果批次或 manifest 原子提交失败、历史保存失败 | 不推进恢复游标；重试写入；禁止把内存结果标为已提交 | 需要处理或失败 | 是 |
| 用户取消/应用退出 | 取消按钮、系统退出、任务代际失效 | 取消新工作，等待实际句柄/推理退出；保存最后可靠边界 | 已取消或中断后可恢复 | 是 |
| 编程/不变量错误 | 越界 descriptor、错误状态转换、未知 schema | 立即停止并保留诊断上下文；不静默降级 | 失败 | 是 |

### 4.1 资源不足的具体语义

资源不足不是“失败后立刻重试”，而是一个有状态的等待循环：

```text
进入等待 → 保存当前可靠边界 → 释放下一块/可回收临时对象
        → 监听压力恢复 + 退避兜底
        → 稳定观察期通过 → 重新准入一个工作单元
```

初始退避建议为 250ms、500ms、1s、2s、5s 上限；实施时应由共享恢复通知唤醒，退避仅作兜底，不得每个任务各自高频轮询。当前 P1 原型已使用共享准入等待和有界退避，恢复通知唤醒仍属于后续完善项。等待期间不持有 coordinator permit，不保留下一窗口的完整 Float 数组，不重复加载模型。等待时长单独统计，不能被 ETA 当作处理速度。

资源压力持续时允许无限等待，但用户可取消。持续等待不自动降级到远程 ASR、另一个模型或有损音频；任何此类策略都需要新的产品确认。资源恢复后先重新检查录音占用、模型租约、输入缓存、磁盘空间和 attempt generation，再继续。

### 4.2 有限重试和幂等

- 资源等待不计入“推理失败重试次数”。
- 同一个 `attemptGeneration + workUnitID + model/config fingerprint` 的模型/解码错误最多自动重试一次；第二次保留上下文并转为用户可重试状态。
- 取消、输入变化、缓存损坏不能通过盲目重试解决；只有重新准备或从阶段起点重跑。
- 每次重试使用新的 attempt generation；旧任务回调、旧结果和旧通知不能修改新状态。
- 持久化失败要重试写入，不重跑推理；只有提交成功才推进游标。
- 清理动作按资源所有权执行：未发布工作文件、队列缓存、历史归档和原始源文件不能互相删除。

### 4.3 用户可见错误

任务行至少区分：`等待系统资源`、`需要处理`、`转录已完成，等待说话人分析`、`失败，可重试`、`已取消`。用户文案说明下一步动作；诊断日志另记 task ID、阶段、work unit、模型 ID、错误类别/代码、资源状态和最后可靠进度，不记录完整路径、音频、转录文本或凭证。

`errorMessage` 不应作为可靠状态机。任务清单保存结构化 `failureKind`、`failureStage`、`retryable`、`lastCommittedWorkUnit`；旧版本缺失字段时按保守的“失败/需重新检查”迁移，不能根据百分比猜测已提交结果。

## 5. 状态模型和恢复语义

将“任务状态、处理阶段、等待原因”分开，不为每种组合创建一个枚举值。以下为目标概念，编码命名可沿用现有类型扩展：

- 状态：排队、执行中、等待资源、需要处理、取消中、已取消、失败、完成。
- 阶段：预处理、转录、说话人分析、保存。
- 等待原因：内存压力、温度压力、前台录音、推理通道占用；可同时存在多个原因。
- 需要处理：音频缓存不可用、检查点不兼容、模型缺失、持久化空间不足等，不能自动进行破坏性修复。
- 进度：展示进度与持久提交游标分开；恢复只信任已成功提交的游标，不使用百分比推算处理位置。
- attempt/generation：每次恢复、重跑和取消产生有效性边界，旧回调不得改写新尝试的任务。

| 事件 | 状态与动作 |
| --- | --- |
| 准入前资源不足 | 进入等待；不加载新模型，不读取下一块，不占执行许可 |
| 推理执行中出现压力 | 停止后续提交；在当前可安全退出边界回收，不假设同步 Metal 调用可强制抢占 |
| 工作单元已完成 | 先持久提交，再推进恢复游标；提交失败不能显示“已可靠保存” |
| 资源恢复并稳定 | 重检任务身份、录音占用、模型/缓存与资源条件后自动继续 |
| 长时间等待 | 保持等待，不自动转失败；尽可能卸载闲置模型并保留可恢复数据 |
| 用户取消 | 立即显示取消中；停止后续调度，等实际工作退出后标记已取消 |
| 解码/推理真实错误 | 失败并记录阶段、块位置和原因，保留最后可靠成果；禁止当作资源等待无限循环 |
| 退出/重启 | 不保存 GPU 状态假装可恢复；重建运行环境，从最后可靠边界继续 |

默认遵循现有 FIFO/用户优先级。资源等待不是开启下一批解码或另一个本地模型的机会；不并发处理后续文件来“绕过”全局压力。未完成、等待中的任务不属于“清理已结束任务”的目标。

取消不删除用户原文件；任务自己的音频缓存、检查点和草稿保留到用户清理，以便显式恢复。完成的历史归档独立拥有音频，清理任务不得删除它。临时未发布文件在实际句柄/推理退出后清理。

## 5. 资源调度与模型生命周期

### 5.1 统一准入

扩展现有 `MeetingLocalInferenceCoordinator`，不并存第二套不一致的 GPU 锁。共享相同的首次/恢复/排队后准入规则。文件任务采用等待策略；其他实时任务当前的错误策略不应被隐式改变。

- OS 内存 warning/critical、温度 serious/critical：不准入新的文件重型推理。
- 在队列里等待不等于持有许可；任务以小型描述符等待，不能持有整段音频和不必要的模型引用。
- 正常资源事件唤醒等待者，温度变化需要对应观察机制；低频复查仅作为兜底，不做每个任务各自的高频轮询。
- 初始恢复稳定期建议 5 秒，持续压力回收阈值建议 15 秒；统一时钟并可注入测试。critical 可以更早请求安全回收，但不得越过尚未退出的推理。
- 只有一个恢复流程可以调度同一任务；反复 normal/warning 抖动不制造多个 waiter 或重复模型加载。
- 等待期间 UI 展示原因和等待时长。运行耗时与等待耗时分开计数，ETA 不用长暂停时间推算识别速度。

### 5.2 资源优先的阶段租约

| 阶段/状态 | 保留 | 释放或不创建 |
| --- | --- | --- |
| ASR 正常执行 | 当前 ASR 模型、当前有界输入、必要推理状态 | 其他文件模型和下一阶段的预加载 |
| 短暂停 | 已可靠成果、必要状态；可短暂保留 ASR 模型 | 未消费音频块、执行许可 |
| 持续内存压力 | 检查点、输入/配置身份、最小调度状态 | 当前窗口、推理临时引用、闲置模型；在安全点处理可回收缓存 |
| ASR → 说话人 | 已保存文本与时间轴、只读音频缓存 | ASR 专属 lease/引用；无其他用户时按资源优先策略卸载 |
| 说话人完成 | 完整说话人结果 | 该阶段 streaming state 和闲置模型 |
| 暂停/等待保存 | 可持久恢复的结果、必要历史事务状态 | 不需要的模型 |

引用释放、模型卸载和缓存清理必须通过已有 manager/引擎所有权协议，在推理实际完成后进行。禁止每块全局 `Memory.clearCache()`；它既不能释放仍被引用的权重，还可能影响其他任务的性能。禁止修改全局模型限制来掩盖单任务状态错误。

压力恢复需要真实观察，不能因卸载请求已发送就认为内存已释放。若无压力恢复信号，保持暂停而非强行重新提交。硬性进程内存预算需实测，不按模型下载大小或当前 RSS 硬猜。

### 5.3 前台录音与抢占

录音优先，但先解耦“文件任务存在”和“会议正在采集”的状态判断；否则等待文件仍可能挡住录音。复用现有停止/清理屏障，在安全边界暂停文件后才让其他流程接管共享模型。文件不得篡改实时会话的 engine/transcriber 字段。

抢占完成前 UI 明确显示正在让出资源；禁止承诺同步解码/Metal 调用能够即时停止。需测试按键连续触发、取消、模型切换和恢复之间的竞态。

## 6. 检查点与结果存储

### 6.1 文件任务独立恢复空间

复用工程已有持久化工具和编码约定，但不能直接共用单个 `meeting-finalization.json`：它属于实时会议恢复，无法代表多个文件任务。文件任务按 UUID 建独立恢复记录，由一个串行存储执行者写入；文件权限 `0600`，恢复目录限制为应用所有。

建议起点是“每任务小 manifest + 不可变的有界结果批次”，避免每完成一小块就重写全部两小时文本。不新增数据库依赖；若利用已有 GRDB 更易保障同一事务的游标与结果，则在实施评审时二选一，禁止两个来源同时成为恢复真相。

建议 manifest 字段：schemaVersion、taskID、attemptGeneration、preparedAudioVersion、音频 sampleCount/rate/内容指纹、模型 ID 与可验证版本/配置指纹、分块算法版本、语言/词典快照摘要、完成阶段、已提交单元范围、结果批次引用、最终 historyEntryID。

源凭证/API key 不进入检查点；记录 provider/model/configuration 标识，执行时重新获取授权。完整媒体指纹可在标准化写盘时增量计算；旧缓存需一次后台有界校验，不能在每块重新哈希整文件。

### 6.2 提交协议

1. 工作单元输出仅在当前 attempt 有效且未被取消时提交。
2. 写完整结果批次并同步/校验，原子发布，再原子推进 manifest；实现必须显式传播存储失败。
3. 只有发布后的连续游标允许恢复跳过；结果已落盘但游标未推进时，可校验接纳或重跑未提交单元，不能漏音频。
4. 任务 UI 的 `tasks.json` 可继续合并写入，但不是可靠结果提交的替代品。
5. 重启清理未发布半成品，校验结果长度/版本/校验值。损坏或不兼容进入“需要处理”，提供有解释的重跑，不静默覆盖已完成结果。
6. 结果按稳定的单元 ID 幂等写入，不能依赖每次随机生成的 segment UUID 判断是否重复。

优先按 ASR descriptor（当前最多 60 秒）提交：可保留本窗口内部的块顺序与重叠消歧边界，突然退出最多重做一个未提交 descriptor。正常短暂停可从当前块继续；持久恢复初期不承诺逐 token 或每个小块恢复。

分块范围必须可重现：要么持久化每个窗口的规划，要么使用固定算法版本、输入和配置重新生成。跨窗口合并保留必要的尾部上下文，不独立处理每块后直接拼接；测试重叠区、静音、窗口边界、空结果和排序，确保恢复不重复、不遗漏。

配置冻结于开始分析；后续设置变化默认只影响新任务。若用户显式要求用新模型重跑，保留有效音频缓存，但使不兼容的 ASR/说话人结果失效。ASR 原生带说话人标签时，不能只按阶段名称猜测可复用范围。

## 7. 说话人阶段的连续性与恢复降级

Sortformer 当前沿 descriptor 复用 streaming state。窗口级让出推理许可可以实现，但不能因此在每个窗口新建 state，造成说话人 ID 漂移。

- 短暂停：保留连续状态，不喂新音频；恢复后接着运行。
- 持续压力需要卸载或进程退出：只有依赖明确支持稳定状态序列化/恢复，且通过跨窗口身份回归后，才允许从中间恢复。
- 若状态恢复不受支持：丢弃未完成的说话人阶段状态，保留完整 ASR，从说话人阶段起点重跑；UI 明确显示，不重做 ASR，不混合两次运行的 speaker ID。
- 任务保存“ASR 完成、说话人未完成”，不以 fallback 原文冒充说话人分析成功。模型缺失或真实算法失败要显示具体状态；资源不足则等待。
- MOSS 原生结构化标签是否足够可靠需单独验证跨窗口身份、混合缺失标签和时间轴。可复用现有保留标签 helper，但不凭 `moss:` 前缀就承诺全文件身份一致；不影响 Qwen 等普通 ASR 路径。

这项限制是能力边界，不为了宣称“所有阶段都支持断点续跑”而保存未经证实有效的模型状态。

## 8. 未完成结果、历史和音频所有权

转录完成且已持久化后开放“查看转录”；转录未完成时本期只显示进度，不额外承诺逐句实时草稿详情。

- 详情采用文件任务草稿来源，复用现有展示组件，不把草稿提前插入普通完成历史。
- 显示“转录已完成／说话人分析等待中”等明确状态；允许查看、复制，若开放导出则带未完成标识。
- 草稿默认只读，不允许直接编辑或重命名待稳定的说话人结果，以免后台更新覆盖用户修改。
- 不因打开草稿触发自动摘要、翻译或其他重推理。当前 history 详情 `handleViewAppear` 会自动摘要，因此必须提供明确的草稿模式/完成标记，不只是放宽打开详情的 guard。
- 说话人完成后同一任务详情更新到完整结果；结果 revision 与 attempt 校验防止旧 UI 回调覆盖新结果。
- 最终历史用稳定关联 ID 幂等提交；崩溃发生在历史已保存、任务尚未标记完成时，应恢复关联而不是创建重复历史。
- 只有所需分析和历史提交都成功后才发完成通知。后续摘要继续遵循用户配置，不改变完成条件来掩盖未完成的分析。

音频优化采取保守方案：分析读取只读缓存，只有最终需要历史音频时才创建独立归档副本；关闭历史音频存储则不复制。草稿回放期间建立读取租约，任务清理须等待释放。缓存不会被历史移动；历史失败/取消只回滚本次拥有的归档，不删除用户文件或其他记录的音频。

此项要在持久化幂等与所有权测试完成后实施，不直接用硬链接/移动代替现有独立副本。保留现有流式复制与磁盘余量检查。

## 9. 后续性能优化候选

| 候选 | 预期收益 | 风险/准入条件 |
| --- | --- | --- |
| 惰性分块，只保留范围索引和当前输入 | 减少窗口内部复制与压力等待时驻留 | 60 秒 Float 本体约 3.84 MB，不能夸大成主要模型内存收益；指针/切片生命周期安全 |
| 固定模型、语言、词典和提示设置快照 | 减少重复解析和上下文查询，保证恢复口径一致 | 不冻结凭证；用户显式重跑才改变配置 |
| 合并过短语音窗口 | 减少小块推理次数及前后处理开销 | 保留连续音频/静音和原时间轴；按模型 A/B，不直接删除静音拼接 |
| 模型专属文件路径/原生流式会话 | 可能减少重复计算和状态初始化 | `generateStream` 不等于跨音频块状态复用；长缓存、准确率和取消需另测 |
| 音频归档复制延后 | 少做失败任务和不保存音频任务的整文件复制 | 本次复制仅约 1.63 秒，不是主要耗时瓶颈 |
| 跳过可靠的重复说话人分析 | 减少一次模型运行 | 只对验证通过的原生标签路径开放，不对所有模型全局跳过 |

一次只引入一个性能变量。不得通过降低位深/采样率、减少必要上下文、跳过弱音来换取表面性能收益。性能 A/B 必须同时检查准确率与说话人归属。

## 10. 分阶段实施与发布门

### P0：基线与可测量性

- 固化本次故障输入、模型/依赖版本、设备和配置；媒体仅存本地，不提交用户视频。
- 记录 OS 压力等级/恢复事件、physical footprint、MLX active/cache memory，以及 CPU/温度/磁盘数据；RSS 继续保留但不作为唯一指标。
- 为资源信号、时钟、模型操作和存储提供可注入测试接口，复用现有测试支持；不靠真实机器过热来驱动单测。

验收：能确定失败原因、等待与执行时长，压力事件的等级/时间不再只是一项 bool；不泄露路径、内容或凭证。

### P1：资源等待与调度一致性

当前已实施的第一步：`.fileASR` 在内存压力、严重温度压力或录音占用期间进入可取消的有界等待，不再把暂时资源压力直接转换为文件任务失败；资源恢复后继续获取推理许可。文件任务收到资源等待事件时显示“等待系统资源”，恢复后回到处理中；其他后台工作仍保持原有拒绝语义，避免实时/普通任务行为被隐式改变。当前等待尚未具备完整恢复稳定期，也未持久化为跨重启检查点。

剩余实施：

- 将等待原因、等待时长和执行/等待耗时映射到任务状态与 ETA，确保界面不显示误导性的“转录中”。
- 完善恢复稳定期、热状态通知、出队统一准入和单次调度，避免恢复抖动或重复加载。
- 支持取消、状态提示和单次调度；修正等待时间对 ETA 的影响。
- 不自动重试任意推理错误，不抢占尚未真正退出的工作。

验收：已完成前序窗口后注入 memory/thermal 压力，下一块不执行也不让任务失败；恢复后继续，取消不会漏接。此阶段可先保留进程内状态，**尚不承诺持续压力下的完整模型卸载或跨重启恢复**，不能将它当成最终资源优先方案。

### P2：持久进度与可回收模型租约

当前已实施的最小切片：每个 ASR descriptor（最多 60 秒）完成后保存一个任务级 JSON 检查点，包含输入样本数、descriptor 数量、模型指纹、已完成窗口数和累计转录片段。下次重试/重启时，输入与模型指纹匹配则从下一个 descriptor 继续；未提交的当前窗口最多重做一次。检查点不保存模型张量、token 流或说话人状态。

剩余实施：

- 落地任务配置/输入身份、原子结果提交和有界恢复数据；ASR 至少按 descriptor 恢复。
- 持续压力时安全保存并释放窗口和可闲置模型；阶段完成即结束阶段租约。当前文件 ASR 完成后会显式结束 ASR active-use 并请求释放闲置 ASR 模型。
- 旧任务迁移、取消、退出和重启恢复；输入/配置不兼容时明确处理。

验收：恢复不重跑已提交的 ASR 单元，突然退出最多重跑一个未提交 descriptor；不存在部分写入被当完整结果。模型真实卸载后按需重新加载，重载不会把原任务静默切换到当前设置的新模型。

### P3：说话人资源边界与草稿交付

- 按第 7 节验证状态能力并实现短暂停/阶段重跑的清晰语义。
- 开放只读未完成转录详情，禁用自动重推理，最终历史幂等升级与完成通知。
- 在 ASR/说话人切换时避免无必要的双模型驻留；明确前台录音抢占与状态解耦。

验收：说话人等待/失败不丢已完成转录；跨窗口说话人身份不因让出许可而改变；草稿不会触发摘要或伪装为完成历史。

### P4：有证据的性能优化

- 在前述安全链路稳定后，分别评估惰性分块、快照复用、短块合并、按需归档和模型专属路径。
- 每项单独报告耗时、内存、CPU/GPU 和质量；没有净收益或引入质量退化则保留原路径。

P1/P2/P3 是同一完整方案的逐步交付，P4 是实验候选。各阶段独立提交、便于审查和回退；不能通过回退版本悄悄读取更高版本检查点。

## 11. 验收矩阵

### 正确性和状态机（确定性测试）

- 内存 warning/critical、温度 serious/critical、多个原因叠加、反复抖动、恢复稳定期；首次准入和排队后准入均覆盖。
- 原生调用中压力/取消、等待时取消、连续重试、退出时保存、旧 attempt 的延迟回调；无失效 continuation、重复执行或资源 lease 泄漏。
- 在输出提交前、结果文件发布后、manifest 发布后、历史提交后分别模拟崩溃；恢复去重、排序、重叠合并及游标不跳跃。
- 低磁盘空间、缓存缺失/篡改、损坏结果批次、未知 schema、模型升级/设置变化；不得损坏原文件或默默重写唯一有效成果。
- 旧 v1/v2 队列兼容：有完整标准化音频但无分析检查点的任务从分析起点开始，不根据百分比伪造续跑位置。升级后的检查点有明确 schema gate。
- 草稿查看/关闭/清理竞态，取消后草稿保留，最终历史只出现一次；分享/导出有未完成提示，自动摘要不提前触发。

### macOS 真机（不可由 Linux 静态检查替代）

- 同设备、同输入和模型，固定电源状态、macOS/依赖版本，对 10/60/180 分钟及用户本次约 2 小时样本各至少 3 次运行，报告中位数和最差一次。
- 轻量 Qwen3 与至少一个更高内存 ASR；MOSS 原生说话人路径、Sortformer 阶段独立测试。不以单模型通过宣称所有模型完成准入。
- 采集各阶段墙钟时间、实际推理时间/等待时间、RTF、RSS、physical footprint、MLX active/cache、CPU/GPU、swap、温度、峰值临时空间、磁盘读写量及 UI hang。
- 定位缓冲/模型/文本/状态各自驻留；持续输入不会导致 PCM 队列线性增长。合法的文本/说话人结果增长应有持久化或有界读取策略，不与音频缓存混为一谈。
- 推理阶段质量：固定人工标注样本比较 CER/WER、DER/说话人身份、时间轴、边界重复和遗漏。P1–P3 不主动改变识别算法，应无流程造成的质量回归；P4 需预先设定并评审质量容差后才准入。
- 系统长时间没有可用预算时允许任务保持暂停，不以“强行跑完”作为成功；不可出现后台无限重试、持续模型加载/卸载抖动或自动失败丢成果。

绝对内存、CPU 和速度目标在 P0 建立设备/模型基线后给出，不先承诺“下降 30%”等未经测量数字。

## 12. 实施前技术核验与保守默认

| 不确定项 | 核验方法 | 无法确认时的默认 |
| --- | --- | --- |
| Sortformer state 是否支持稳定序列化 | 检查锁定依赖 API、状态结构和恢复后 speaker 一致性测试 | 只支持短暂停；卸载/重启后重跑说话人阶段，保留 ASR |
| MOSS 跨窗口 speaker ID 是否全局一致 | 固定多人会议、交替出场、重叠发言回归 | 不默认跳过独立分析、不混合不可靠标签 |
| MLX 缓存回收的真实收益与安全边界 | 无活跃推理时比较 active/cache/footprint 与重载耗时 | 只执行已验证的 manager 闲置释放，不全局频繁清缓存 |
| 内存压力来源与恢复通知特性 | macOS 实测 normal/warning/critical、footprint 和系统压力时间线 | 保留保护，持续等待；不以低 RSS 否定系统信号 |
| 文件草稿和历史能否共用一份音频所有权 | 审查现有 move/import、rollback 和 clear 路径 | 独立归档副本，不共享可被清理的路径 |
| 结果存储采用 manifest 还是既有 GRDB | P2 原型比较原子性、增量写入与恢复复杂度 | 一个权威来源；不扩展现有实时会议单检查点来承担多文件恢复 |

以上是不阻塞方案制定的技术核验，不需要用户猜测底层 API 能力。如核验会改变已确认的产品体验（例如不再自动恢复、改用远程服务、隐藏部分结果），必须重新确认，而不是悄悄降级。
