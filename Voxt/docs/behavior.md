# 行为对照：Voxt 怎么做 / VoxtNew 怎么做 / 为什么

本文继承自 Auralink（VoxtNew 由它复制而来，见 NOTICE），各节标题里的 M1–M6 是 Auralink 的里程碑；VoxtNew 的里程碑见 [plan.md](plan.md)。功能和行为参考 Voxt（`hehehai/voxt` @ `baa6f31`，1.15.0），本仓以前的 `Voxt/` 也是它（已删除）；VoxtNew 可以直接移植 Voxt 的代码（同一作者，Apache-2.0），但仍按自己的结构组织。每个模块落地时，在这里补一节对照表，作为评审依据：

- **Voxt 怎么做**：写清楚出处（源码文件或文档）。
- **VoxtNew 怎么做**：写实际实现的行为，并指向实现它的包或文件。
- **为什么**：保留的写保留理由；改掉的写改的理由。

状态：✅ 已实现　◐ 部分实现（骨架或接口已经有了）　○ 计划中（写明负责的里程碑）

## 1. 架构原则（方案 §1）

| # | Voxt 怎么做 | VoxtNew 怎么做 | 为什么 | 状态 |
|---|---|---|---|---|
| 1.1 | 会话状态分散在 `AppDelegate` 的 43 个 extension 里（`Voxt/App/*Flow.swift`、`Recording/`），取消和收尾由各个 Flow 各自处理 | 一个 `Session` 状态机（idle → recording → recognizing → composing → delivering → done/cancelled/failed）是会话唯一的所有者；所有异步回调都带 sessionID，迟到的一律丢弃 | 身份、取消、“只收尾一次”集中在一个地方，才能写表驱动测试；迟到回调不会污染下一次会话 | ✅ M3：`internal/session`（§5）；helper 的 job 通知也带 `job`，supervisor 丢弃已结束 job 的迟到通知 |
| 1.2 | 语音翻译“先增强、再翻译”，两次 LLM 请求（`docs/Prompt.zh-CN.md`“语音翻译”一节） | 一次会话最多一次 LLM 请求：Prompt Composer 按“功能 × 能力 × 场景 × 词典 × 语言”拼出一个请求 | 少一次往返，延迟和费用减半；两段式在第二段会丢掉第一段的上下文 | ✅ M3 转录、M4 翻译和转写（`internal/compose`，§5、§6）；翻译只有“看起来没翻译”时才多一次严格重试 |
| 1.3 | 命中应用增强分组时，用分组 prompt **整个替换**全局 prompt（`Core/EnhancementPromptResolver.swift`） | 分组 prompt 作为“场景层”**叠加**在基础清理之上 | 用户写的分组规则不完整时，基础清理（去口头语、标点）不会跟着丢 | ✅ M5（§7） |
| 1.4 | 规则匹配、prompt 拼接和 AppKit 调用写在一起 | 匹配、组合、热键判定、文本后处理是纯 Go 函数，Linux 上做表驱动测试；录音、事件 tap、AX、粘贴放在窄接口后面，测试换成假实现 | 不需要 Mac 也能测完整链路 | ◐ M1：helper 进程和协议、假 helper（`helpertest`）、`permission.Fake`、in-process 的假 supervisor 都已就位 |
| 1.5 | 设置保存在 UserDefaults 的几百个键里（`Voxt/` 中有 259 处 `UserDefaults`），还保留了旧版单热键之类的迁移代码 | 设置是一个带版本号的类型化文档（`internal/settings`，v1），存在 SQLite 的 `documents` 表里；不兼容、也不读取 Voxt 的键 | 从 v1 开始，没有历史包袱；整个文档可以快照、比较、重置 | ✅ M1 |
| 1.6 | 读输入框用了 CDP（`App/TextInputCDP.swift`），还有截图、窗口上下文等链路 | 不做 CDP、截图和窗口上下文 | 已废弃或小众，权限和维护成本高（方案 §2“不做”） | ✅（不实现） |

## 3. 模型（VoxtNew：语音识别在本机，语言模型用远程服务）

2.1 起（团队 11-06 的决定）：语言模型只用远程服务（OpenAI 兼容 API，见 3.32），本地语言模型退役（3.33）；下面 3.10–3.31 讲的 `voxtnew-llm` 之后从代码里移除了（`llm/`、`internal/llmrt`、llm 协议），这些条目只作记录；本地语言模型的目录条目留着，让用户能在模型页删掉旧文件。

Auralink 的这一节对照的是远程 ASR / LLM 服务（豆包、阿里百炼、OpenAI 兼容、阶跃、DeepSeek 等），VoxtNew 在 M0 删掉了整个远程层（docs/architecture.md §5），这一节随之删去。本地模型的对照（Omni 运行时的生命周期、各模型的 Final 请求策略、实时预览节奏、Silero VAD、模型目录与固定版本）在 M1–M3 落地时补在这里，出处是 Voxt 的 `OmniASRRuntime.swift` 等。

| # | Voxt 怎么做 | VoxtNew 怎么做 | 为什么 | 状态 |
|---|---|---|---|---|
| 3.1 | 模型目录很长：多个 ASR 系列、十几个 MLX LLM 和两个 GGUF，界面上写系列名、量化、评分和标签；下载时先查 Hub 的文件树，按扩展名过滤，按大小校验；模型放在自己的 `~/Library/Application Support/Voxt/model-storage/`（HF 缓存布局） | 模型不多（`internal/models`）：精准 / 快速语音识别（另有 3.47 的 Voxt 1.x 其他本地模型）、人声检测（内置，不让选，随第一个语音模型安装）、均衡 / 快速语言模型、翻译专用模型，每个钉住 ActNow 家族 pins 表里的 commit（`actnowkit/models.PinsOfApp("voxtnew")`，`TestFamilyPins`；表里没有的 Voxt 1.x 模型不查，运行时也不读这张表；omni 的同时与 `sglang_omni_mlx/native/ci/` 的 `models.json` 或 `model_pins.json` 一致，`TestOmniPins`），列出用到的文件和每个文件的 SHA-256（Hy-MT2 只下一个 GGUF，Qwen3.5-4B-OptiQ 不下 `optiq/`），带家族的 `family`、`quant`。**模型放在 `$HUB`**（默认 Voxt 自己的 `~/Library/Application Support/SGLang Omni/models`，跟随家族设置 `models.root` 时用它；标准 HF 布局）。2.0.0 用的是家族模型库 `ActNow/models/hub`：启动时目录里的模型从那里硬链接过来（`Manager.Import`），AudioSmith、Dicta 下载过的也一样，不用重新下载。和家族共用同一个模型库（`models.root`）时：别的 app 已经下载过的同一 `repo@commit`（如快速语音识别 = Qwen3-ASR-0.6B-4bit `313d8501`）不再下载：没有别的 app 声明的直接算 VoxtNew 已安装；别的 app 声明着的显示“由 AudioSmith 安装”，在引导的复用卡片或本地模型页点“直接使用”后（声明 origin `reused`）才归 VoxtNew 用，此后“从 VoxtNew 移除”只去掉 VoxtNew 的声明，它又回到“由 AudioSmith 安装”；运行时从 `snapshots/<commit>` 加载。另有两个**借用的**语言模型（`Borrowed`：家族的 Qwen3-4B-Instruct-2507、Gemma 4 E4B），VoxtNew 从不下载，只在别的 app 装了、用户选择使用后出现，作为均衡 / 快速模型的 `alternatives`；精准语音识别的 alternative 是快速语音识别。界面只用朴素的话说擅长什么、支持哪些语言、多大，不显示仓库、系列和量化 | 用户只需要最好的几个，参数由我们调好；固定 commit + 哈希，下载到的就是测过的那份。家族规范 v1.0.3 §7（§17 Q7 已定）：VoxtNew 不另建模型目录，与家族共用模型库，装过 AudioSmith / Dicta 的用户免下载。2.0.1 起按团队的决定改了：模型由 SGLang Omni 的运行时加载，默认目录以它命名（与 §17 Q7 不同）；免下载靠启动时的硬链接，共用靠家族的 `models.root` | ✅ M1b，家族 F1 |
