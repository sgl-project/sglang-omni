# Source layout and runtime boundaries

Voxt is a macOS 26.2+ menu bar application, built with the shared `Voxt` Xcode scheme. Build instructions live in [CONTRIBUTING](../CONTRIBUTING.md); dependency pins and model validation requirements live in [MLXAudioDependency](MLXAudioDependency.md).

## Source map

| Directory | Responsibility |
| --- | --- |
| `Voxt/App/` | Application lifecycle, dependency assembly, feature routing, text delivery and window coordination |
| `Voxt/App/Recording/` | Recording start/stop, capture and output routing |
| `Voxt/Core/` | Shared values, persistence, preferences, prompts, security, logging and runtime support |
| `Voxt/Core/LLM/` | Execution plans, provider payloads, remote requests, parsing and answer models |
| `Voxt/Core/History/`, `Voxt/Core/Dictionary/` | Domain stores, repositories and query/value support |
| `Voxt/Core/Notes/` | Note storage, external export state and Obsidian/Reminders sync |
| `Voxt/Core/Models/` | Local LLM/GGUF loading, installation, downloads and model storage support |
| `Voxt/Core/Transcription/` | Capture metrics, VAD planning, ASR hints and transcript support |
| `Voxt/Transcription/` | Native HTTP speech adapters, ASR model management and shared contracts |
| `Voxt/Transcription/RemoteASR/` | Remote ASR capture, upload and streaming protocols |
| `Voxt/Meeting/` | Meeting coordination and live sessions; capture, processing and speaker-analysis subdomains |
| `Voxt/Hotkey/` | Event handling, trigger rules, preferences and shortcut recording |
| `Voxt/Settings/` | SwiftUI settings and onboarding; `Shell/` owns navigation and shared presentation |
| `Voxt/Windows/` | AppKit windows, overlays, detail views and their view models |
| `Voxt/Resources/`, `*.lproj`, assets | Bundled prompts, runtimes, localization and visual resources |
| `VoxtTests/` | App tests; `TestSupport/` contains shared fixtures, doubles and model-test gates |
| `Packages/OmniModelArtifacts/` | Bounded artifact validation, cooperating directory leases, preparation and atomic publication; Foundation/system POSIX only, no model loading |
| `tools/`, `Config/`, `packaging/` | Validation/build scripts, signing configuration and packaging inputs |

`Voxt/Voxt/Info.plist` is referenced by the build settings; the nested directory is not an orphan. There is no `Voxt/UI/` directory. The app and app-test targets use file-system-synchronized Xcode groups. Preserve membership exceptions and resource references when moving files.

## Main paths

- `AppDelegate` assembles model managers, stores, transcribers and UI coordinators. Its extensions route hotkeys, recording, translation, rewrite, notes and meetings. `LLMRequestLifecycle` owns request validity and outstanding work; `TrackedTaskStore` retains cancelled capture/LLM/audio submission tasks until exit rather than treating cancellation as completion.
- Recording selects a `TranscriberProtocol` implementation. Planning, merging, preview text, capture buffers, detached inference and structured segment conversion are separate under `Transcription/`. `MLXTranscriber` retains task cancellation, session revision and model leases; its historical name does not imply a Swift Audio numerical backend.
- LLM tasks compile into requests before local or remote execution. `RemoteLLMRuntimeClient` routes compiled requests; sibling extensions own Responses execution, chat completion execution, request construction, provider settings and runtime policy. Existing endpoint/message/parser helpers remain shared with connectivity checks.
- Translation and strict retry share AppDelegate's private execution path without merging their diagnostic/provider-resolution differences or rewrite conversation semantics. `TextTransformPromptSupport` contains pure template delivery and bounded rewrite conversation prompts; AppDelegate retains configuration/glossary reads and all request/session/UI state.
- `RecordingVoiceActivityFrameDecider` keeps the complete VAD actor, private detectors/warning state and decision/stat values together. Capture startup, session state, silence-monitor tasks, segmenter/drain state and stop-flush orchestration remain in `RecordingCaptureFlow` and AppDelegate.
- `RecordingSessionLifecycle` controls identity, cancellation and exactly-once output/end admission. Final output is an immutable `SessionFinalizeContext`; delivery checks that session before recording history and dictionary evidence. `TextInputIO` owns input inspection, `TextOutputDelivery` owns paste/key integration, and `TextInjectionTransaction` validates queued work. Output generations reject stale begin/cancel/dismiss, while temporary clipboard restoration checks write ownership. There is no editor acknowledgement or cross-process clipboard CAS.
- Remote ASR retains recording/generation ownership in `RemoteASRTranscriber`. Response actors freeze terminal text and respect cancellation. Dictation and meetings share bounded Doubao framing/gzip and Aliyun endpoint helpers, not their different transcript projection policies.
- Meeting coordination combines microphone/system audio, live transcription and final processing. `MeetingLiveSessionRegistry` pairs sessions with tokens, including draining sessions. Cleanup precedes archive/VAD/model reuse. File imports have a per-import task/transcriber/audio/model-use owner. Live finalization keeps its stop barrier through checkpoint cleanup; real device/model acceptance remains separate.
- History and dictionary persistence use repositories backed by `VoxtDatabase` (GRDB/SQLite), with legacy-data migration. `HistoryEntryPolicy` projects correction/term/segment values and retention cutoffs from explicit snapshots; history pagination/generations, publication, database/audio writes and the late retention-count read stay in `TranscriptionHistoryStore`. Domain/Codable values are separate from stores' snapshots, caches and writes. `VoxtNoteModels` retains the existing value and SwiftData entity schema; `VoxtNoteQueries` computes ordering/sections/manual-rank projections from explicit snapshots, while `VoxtNoteStore` alone applies record changes, saves, reloads and recovers storage. Notes and external sync have separate owners. New history scans write directly to the dictionary; retired discovery work no longer runs, while old suggestion snapshots remain decodable. `DictionaryEntryPolicy` receives explicit entry/category/index snapshots and shares existing input/confidence/variant/boundary decisions; repository writes, publication order and reload generations stay in `DictionaryStore`. Its preexisting asynchronous reload and best-effort write limitations are not silently changed by extraction.

Resumable transfer is shared under `Core/Models`; managers retain install/download state, storage revisions and load lifetimes. Stateless `MLXModelDownloadAttempt` and `MLXModelArtifactPreparation` consume explicit endpoints/roots/progress and reuse existing transfer, validation and publication support rather than sharing manager state. `CustomLLMModelDownloadAttempt` similarly performs ordered transfer while its manager retains polling-task registration and generation guards; `CustomLLMRequestDiagnostics` constructs metrics without taking model/stream/publication ownership. `MLXAudioCaptureGraph` similarly borrows the transcriber's engine without taking session ownership; correction and buffered transcription share final request orchestration in `MLXDetachedInference`. Shared loading uses `SharedModelLoadCoordinator<Value>`: current waiter entries and outstanding loading tasks have different lifetimes. Cancelled generations remain waitable by shutdown and block idle reclamation until they return. Shutdown callers share one cleanup task.

## Native HTTP boundary

Local ASR, Silero and Sortformer execute in the existing Native server subprocesses through their HTTP/WebSocket protocols. The shared `sglang_omni_mlx/native` package is not a Voxt extension point: keep it identical to the officially merged source, with future synchronization through normal official-main merges. Voxt owns request conversion, process management and model-storage coordination outside that package.

The abandoned XPC service, C ABI wrappers, typed-engine extraction, helper/client/contracts, App Group configurations and smoke tools are removed. XPC is not a pending production factory or release gate. This does not restore the Swift Audio fallback: the app still has no AudioSTT/VAD/Core product/package/pin. Keep MLX Swift LLM/VLM/MLX, Tokenizers/HuggingFace, llama.swift, Remote routes, saved model choices and installed directories.

All eleven ASR catalog checkpoints map to the existing seven-family Native HTTP servers. Qwen/MOSS/Nemotron have realtime routes; Whisper/Cohere/Parakeet/SenseVoice retain batch-preview behavior. Family options, language/hint settings, chunk cadence and longform remain at the existing caller boundaries. No former 30-second validation transport cap becomes a production recording limit.

`OmniASRRuntime` acquires a canonical cooperating directory reader before spawning a child and retains it through actual process exit. Shutdown first requests graceful exit, then escalates termination signals; timeout is not exit proof. A running child retains its runtime even after callers drop it. The last endpoint use releases that exact process scope, not a replacement. Socket cancellation, stream completion and task settlement do not prove per-stream GPU drain in an unchanged server.

Silero detectors serialize preparation, exchanges, reset and unload, preserving whole-audio offline processing and completed-frame stream probabilities. Sortformer uses an app-owned Foundation configuration for the ordinary approximately five-second feed scheduler. Its exact runtime lease and serialized session tail retain readers/admission through file completion or failure cleanup. The unused legacy realtime annotation actor was removed after caller/selector/resource audit; no new 24-second whole-window route was introduced.

Auxiliary provisioning validates bounded config/safetensors structure with `OmniModelArtifacts`, without loading tensors or Swift Audio models. Structural validation does not establish model-key compatibility, immutable weights, blob hashes or numerical quality. Atomic publication requires cooperating readers/exclusive mutation and canonical sibling staging; a committed replacement remains successful if old-payload cleanup fails. Failed staging remains for deliberate recovery, not blind resume. Preparation copies dereferenced regular files under source/staging readers and explicit budgets.

These readers do not protect hostile namespace changes, external blob writes, power-loss/fsync durability or an App crash that releases locks before an orphaned server exits. Cache/blob/repair/orphan recovery remains unfinished. Run `swift test --package-path Voxt/Packages/OmniModelArtifacts` without models; portable tests are not real Metal/model acceptance. See the [Native HTTP migration plan](../plan/NativeHTTPMigrationPlan.zh-CN.md).

## Permission and input boundaries

LLM requests are text-only. Automatic foreground-window text/structure capture, screenshots, image attachment models and debug capture have been removed. App identity snapshots still support App Branch, dictionary scope and delivery targeting; selected-text operations remain. Some text-generation checkpoints still require MLXVLM's loading factory.

Global hotkeys and shortcut recording use Accessibility-backed modifying event taps, with local recording fallback, not Input Monitoring/HID listeners. Recording mute restores only owned output-device changes and also mutes Voxt sounds. Meeting system audio uses a public Core Audio process tap and requests access at capture start without private TCC preflight. Screen Recording is no longer requested. See the [implementation and pending macOS validation](ContextEnhancementRemovalImplementation.zh-CN.md).

## Maintenance and acceptance

Most features remain in one app target. `AppDelegate` owns cross-feature state, and some shared preference types remain under `Settings`; directories alone do not enforce dependency boundaries. Reuse existing owners before introducing abstractions, split by ownership rather than arbitrary line counts, and do not broaden private state merely to enable extraction.

Preserve default MainActor isolation, approachable concurrency, explicit `nonisolated`, `Sendable`, cancellation and buffer-lock assumptions. Existing unchecked Sendable types require case-by-case review. `MLXNativeLiveRuntime` owns stream/feed/event tasks and transferred model use; task completion or synchronous cancellation must not be relabeled as a Native GPU barrier. Whole-model shutdown is observable through actual child exit.

Hotkey tap installations own callback context, sources and threads separately from routing; queued work is generation-scoped and business actions run outside the routing lock. Modifier specificity, trigger rank and strict-superset decisions live in the existing stateless `HotkeyModifierInterpreter`; the manager still owns private routed values, cache, locks and gesture state. `MeetingDetail` separates setup, layout, playback and read-only presentation, while its view model keeps async mutable state and the view keeps player/scroll synchronization. `MeetingDetailTranscriptProjection` transforms explicit segment/language/failure snapshots without persistence or task ownership. Model debug windows retain complete private ASR/recorder and LLM owners in separate files; `ModelDebugWindowValues` holds shared presentation values, not their tasks or resources.

Settings/sidebar/dialog and history-row splits retain their original SwiftUI ownership. `HistorySettingsLists` contains stateless note and paged-entry presentation with explicit snapshot/callback inputs; `HistorySettingsView` retains preferences, selection/search/paging generations, height cache, row mutations, tasks and storage actions. The new view boundaries still require manual focus/scroll/editing checks. `OverlayTranslationMenuPicker` keeps its private representable/coordinator and complete NSView/NSMenuDelegate/event-monitor owner together; conversation/bubble/waveform components retain their state and callbacks in the answer-card components file. `FeatureSettingsNormalization` reads explicit settings/fallback values and the existing prompt/catalog policy without writing preferences or calling the store. `FeatureSettingsStore` retains migration, load/save, legacy writes and notifications. The retired settings table/provider-card selection subgraph is removed; live catalog/configuration and persisted AppStorage declarations remain. Permission/provider/connectivity support retains its authorization and timeout policies. `RemoteProviderSheetOperations` owns scoped requests and retirement; socket close precedes waiting on timed-out receives. Onboarding extensions are not separate state owners.

Installation presence is asynchronous: unknown is not missing. Settings consume shared debounced revision notifications, not polling every progress change. Structured logs redact sensitive keys/values recursively. Retiring MLX/remote-preview tasks, serialized meeting VAD cleanup and stale dictionary-read protection are documented in the [closeout checklist](RefactoringCloseout.zh-CN.md).

Captured pre-unlink AudioCore DSP fixtures and independently supplied Silero/Sortformer references replace linked-library test oracles. Fresh no-XPC verification includes the actual Mac App/TestDebug suite (1975: 1933 passed, 42 skipped, zero failures), rebuilt official Native runtime, public-fixture Qwen CLI comparison, ten real Silero HTTP/parity/reader checks and final App artifact audit. Earlier Core/helper/XPC snapshots are historical evidence, not inherited acceptance. Optional-reference skips are not parity passes. Full model quality, GUI/permissions, long-meeting memory/performance, Intel/Release/clean-machine and recovery acceptance remain pending.
