# Ming3 audio MTP decoding on MLX

The native Ming3 audio server and CLI accept `--mtp 1` to enable the checkpoint's single next-token prediction layer. The default remains ordinary greedy decoding. This uses the existing MTP weights in the pinned `inclusionAI/Ming-3.0-audio-tiny` checkpoint; no separate draft download is needed.

The MTP layer pairs normalized target hidden states with the next committed token embedding. The target verifies the anchor and one proposed token together. On rejection, the runtime restores every base layer's attention, convolution and recurrent state, then replays the anchor. The MTP cache advances only with committed target states. Replaying rejected blocks is a correctness-first implementation whose performance must be measured; it may lose speed when acceptance is low.

Build with `-DSGLANG_OMNI_MLX_BUILD_TESTS=ON`, then build `ming3_mtp_probe`. Set `NATIVE_RUNTIME_BIN` to the build directory and run `pytest tests/test_ming3_mtp.py`. Seeded reduced checkpoints run the actual native audio, KDA, MLA and MoE operators to check accepted/rejected proposals, budgets, cancellation and request isolation. Run the chat protocol tests with `NATIVE_STUB_SERVER` as well. These tests do not replace full-model correctness and performance experiments.

Before marking this draft ready, run `ci/benchmark_speculative.py` on the final committed source with the frozen 392-clip corpus and a SHA-256-pinned long-audio manifest. It uses the existing golden prompt, ordinary and accelerated resident HTTP servers in plain/draft/draft/plain order, separate warmup records, per-language timing/acceptance and unchanged golden checks. Include 16 AMI windows and the 310-second ES2005a meeting excerpt. The latter uses a 4096-token output budget in both modes; truncated results remain visible and must not be reported as successful complete transcripts. This exercises the native chat route, not a new Voxt model integration.

Run Mac CI and repeat measurements after changing the tested commit or merging a new base.
