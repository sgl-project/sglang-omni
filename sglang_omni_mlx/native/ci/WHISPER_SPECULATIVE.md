# Whisper distil decoding on MLX

The native Whisper server and CLI accept `--draft-model-path DIR --draft-steps 7`. The draft proposes autoregressively, and the target verifies a causal block, retaining only its accepted prefix. Greedy requests use the draft; requests with positive temperature keep the existing sampling path. Omitting the draft preserves the original decoder. This is a separate distil decoder, not MTP.

Use the target and tokenizer pinned by `model_pins.json` for `mlx-community/whisper-large-v3-mlx`, and the pinned `wilsonzheng0327/Whisper-large-v3-distil-draft` checkpoint. Convert the latter once with `python ci/convert_whisper_draft.py HF_DIRECTORY NATIVE_DIRECTORY`. Startup checks all encoder tensors against the target with the same half-precision tolerance as the CUDA implementation, then releases the draft encoder and shares the target's encoder states. The target tokenizer, suppression rules and language prompt govern both paths.

`tests/test_whisper_speculative.py` runs real native inference on seeded small checkpoints. Set `NATIVE_RUNTIME_BIN` to the build directory and run pytest. It covers accepted and rejected proposals, EOS, generation budgets, repeated requests and incompatible encoders.

Before marking this draft ready, run `ci/benchmark_speculative.py` on the final committed source with the frozen 392-clip corpus and a SHA-256-pinned long-audio manifest. The runner uses fresh resident servers in plain/draft/draft/plain order, excludes a recorded warmup, uses the supervised HTTP request path, preserves per-request transcripts and timing, reports language groups and draft acceptance, and checks the existing goldens without rewriting them. A full run needs 16 AMI windows (30/60/90/120 seconds) and the 310-second ES2005a meeting excerpt. Whisper processes long audio in its existing 30-second windows; it does not exercise MOSS chunked prefill.

The benchmark reports end-to-end request time, including audio encoding, and counts accepted draft tokens separately from target correction/bonus tokens. Review all output differences, length-limited samples, repeated-run variability and quality metrics before drawing a speed conclusion. A smoke run is not full-corpus evidence. Run Mac CI and rerun benchmarks after any implementation or base merge that changes the tested commit. No acceleration claim is made before those measurements.
